# ADR 0003: Семантика неполного окна SMA по отсчётам

Статус: заменено ADR 0004
Дата: 2026-07-25

<a id="context"></a>

## Контекст

`SimpleMovingAverage` по числу отсчётов сохраняла верную частичную сумму, но всегда
делила на полный период. SMA с периодом 10 при первом значении 100 выдавала 10
вместо 100. Это не среднее и не явный пропуск, а искусственное нарастание ML-признака.

Общий контракт прогрева пока не определён. Вопрос, должны ли все скользящие
индикаторы скрывать выход до полного окна, рассматривается отдельно от исправления
арифметики SMA.

Библиотека разрабатывается; версия JSON пока обозначает схему, а не каждое
изменение численного поведения.

<a id="decision"></a>

## Решение

После хотя бы одного подходящего отсчёта SMA выдаёт среднее арифметическое
доступных окну отсчётов. Делитель:

```text
min(number of buffered samples, configured window period)
```

После заполнения усредняются ровно последние `period` отсчётов.

Поведение отдельного индикатора без отсчётов прежнее. Ячейки экстрактора остаются
NaN до первой записи, затем SMA пишет частичное среднее.

Это решение не задаёт общую готовность других индикаторов и не требует NaN до
полного окна. Эта политика отложена.

`FEATURE_SET_FORMAT_VERSION` остаётся `1.0.0`: исправление до выпуска не меняет
версию артефакта.

<a id="consequences"></a>

## Последствия

- Частичные и установившиеся средние имеют один масштаб.
- Постоянный вход даёт ту же постоянную SMA с первого отсчёта.
- Каждое окно имеет собственный делитель, ограниченный периодом.
- Пересчёт существующих потоков и сохранённых признаков с неполными окнами даст
  другие значения.
- Будущая общая политика прогрева сможет скрывать корректные частичные средние
  без изменения арифметики.
