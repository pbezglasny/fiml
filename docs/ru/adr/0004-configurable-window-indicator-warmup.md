# ADR 0004: Настраиваемый прогрев оконных индикаторов

> Уточнение порядка (2026-09-08): порядок и продвижение временных окон теперь
> определяются для каждого символа по всем видам событий. Глобальные тики Time
> влияют только на GLOBAL; календарные признаки следуют максимальной принятой
> метке. Это заменяет формулировки о глобальном порядке/истечении ниже.

Статус: принято\
Дата: 2026-07-26

<a id="context"></a>

## Контекст

До накопления истории индикаторы выдавали несогласованные значения: SMA —
частичное среднее, EMA — начальное значение, накопительные — частичные суммы.
Временные индикаторы продвигались только подходящими событиями; их готовность
и значения могли устаревать при продвижении глобального времени.

Для согласованности обучения/применения нужен единый контракт пропусков, но некоторым
моделям нужны частичные значения. Готовность должна быть явной, а не выводиться
из NaN: готовое временное среднее может иметь пустое текущее окно.

ADR 0003 определил арифметику частичной SMA, отложив общий прогрев. Этот ADR заменяет
ту политику выхода. Расчёт SMA может хранить верное частичное среднее, пока выход
признака его скрывает.

<a id="decision"></a>

## Решение

У оконных индикаторов с частичными значениями одна `WarmupPolicy`.
Исключение — точные лаги доходности ниже.

```rust
pub enum WarmupPolicy {
    FirstValue,
    FullWindow,
}
```

Политика действует на все выходы группы. Каждый готов независимо по своему окну.
Готовность монотонна и сбрасывается только при сбросе/пересоздании индикатора.

`FirstValue` делает все выходы готовыми после первого подходящего входа.
`FullWindow` задаёт правила:

- SMA по отсчётам, EMA, CVD ждут число подходящих входов, равное периоду;
- временные SMA, OBV, число сделок ждут продвижения глобального времени на полную
  длительность окна от первого подходящего входа.

Пустые интервалы агрегации считаются наблюдаемым временем. Временные индикаторы
наблюдают каждое событие, продвигая готовность и удаляя истёкшие интервалы даже без
подходящих рыночных событий.

Готовая временная SMA с пустым окном не имеет значения. Временные OBV и число
сделок используют ноль для наблюдаемого пустого окна. Готовность не означает
доступность текущего значения.

Отдельные индикаторы имеют `is_ready_at(index)` и `is_ready()` для одного/всех
выходов. `value_at(index)` возвращает `None` при прогреве, недоступности или
отсутствии конфигурации выхода.

Ячейки вектора — `f64`, начинаются с NaN и остаются NaN, пока `value_at` даёт `None`.
Decimal не может представить такой контракт пропуска.

<a id="refinement-exact-sample-lag-returns-issue-102"></a>

### Уточнение: точные лаги доходности по отсчётам (задача #102)

Положительный лаг `k` сравнивает цену с ценой ровно `k` подходящих отсчётов назад.
Выход готов после `k+1` отсчётов; короткие лаги могут быть готовы раньше длинных.
Лаг не сокращается при прогреве, будущие отсчёты не используются. `FirstValue` и
`FullWindow` неприменимы: отдельные доходности, ключи, Python и JSON не принимают
политику. JSON с `warmup_policy` доходности отклоняется.

История продвигается только настроенным символом/скалярным источником. Price и
trade-price имеют разные истории; другие символы, объёмы и время их не меняют.
Совместимые лаги разделяют заранее выделенный кольцевой буфер `max(lags)+1`.

Простая доходность — долевое изменение `current / previous - 1`, вычисляемое как
`(current - previous) / previous` в `f64`. Недостаточная история и знаменатель
`+0.0`/`-0.0` дают `None` в отдельном Rust и NaN в векторе. Конечные отрицательные
цены используют обычную арифметику; текущий ноль с ненулевым знаменателем даёт `-1`.
Нули и отрицательные отсчёты продвигают историю. После накопления истории готовность
сохраняется и при нулевом знаменателе; значение восстанавливается при ненулевом.
Логарифмическая доходность имеет ту же готовность, но требует положительных цен.

Контракт сохраняет сигнатуры, канонические ID и спецификацию `2.0`.
Общие буквальные снимки Rust/Python — `tests/fixtures/sample_returns.json`.

<a id="refinement-sample-window-return-volatility-issue-103"></a>

### Уточнение: волатильность доходности по отсчётам (задача #103)

`RollingVolatility` и `volatility` считают стандартное отклонение генеральной
совокупности одношаговых доходностей `(current - previous) / previous` без
годового пересчёта. Окно `N` хранит последние `N` корректных доходностей, не цен.
Дисперсия делится на число доходностей, не на число минус один; одна даёт ноль.

Первая цена задаёт базу. Знаковый ноль в знаменателе пропускает доходность, но
продвигает базовую цену. Пропуск не занимает слот, не вытесняет наблюдения, не
сбрасывает готовность и не меняет имеющийся выход. Отрицательные конечные цены
используют обычную арифметику; текущий ноль после ненулевой цены даёт `-1`.

`FullWindow` требует `N` корректных доходностей (минимум `N+1` цен, при пропусках
больше). `FirstValue` готов с первой цены, но не имеет значения до первой
корректной доходности. Готовность монотонна и независима для окон.
Недоступность — `None` в отдельном Rust, NaN в векторе.

Историю продвигают только подходящие символ/источник. Истории price/trade-price
независимы; другие символы, виды и время выходы не меняют. Совместимые окна разделяют
буфер доходностей. API, ID и версия `2.0` сохраняются. Общие снимки
`tests/fixtures/sample_volatility.json` проверяют значения, прогрев, пропуски и вытеснение.

<a id="configuration-and-parity"></a>

## Конфигурация и совпадение

Для индикаторов с частичными значениями `WarmupPolicy` хранится в каждом оконном
`IndicatorSpec` и записывается как `"first_value"`/`"full_window"`.
Она не входит в идентичность или каноническое имя.

Конструкторы отдельных индикаторов Rust требуют политику явно. Построители
спецификации Rust по умолчанию используют `FullWindow` и имеют явные варианты.
Python предоставляет `WarmupPolicy.FIRST_VALUE` и `WarmupPolicy.FULL_WINDOW`.

Версия сериализации остаётся `1.0.0`. Совместимость со старыми артефактами
разработки намеренно не сохраняется.

Неоконные признаки не принимают политику и готовы при первом значении.
Публичная агрегация `all_ready()` отложена.

<a id="consequences"></a>

## Последствия

- Выходы для ML дают NaN до накопления настроенной истории.
- Частичные значения явно включаются через `FirstValue`.
- Короткие окна могут открываться раньше длинных.
- Временные значения и готовность отражают глобальную границу времени, включая
  тишину и события других символов.
- Готовность можно агрегировать без поиска NaN по выходам.
- Конструкторы Rust, сериализованные спецификации и сборки Decimal несовместимо
  меняются в период разработки до выпуска.
