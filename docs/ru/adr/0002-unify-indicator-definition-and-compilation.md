# ADR 0002: Единое определение и компиляция индикаторов

> Уточнение порядка (2026-09-08): порядок и продвижение временных окон теперь
> определяются отдельно для символа по всем видам событий. Глобальные тики Time
> влияют только на GLOBAL; календарные признаки следуют максимальной принятой
> метке. Это заменяет формулировки о глобальном порядке/истечении ниже.

Статус: принято\
Дата: 2026-07-16

<a id="context"></a>

## Контекст

У встроенных признаков две параллельные модели создания:

- `FeatureExtractorSpec` описывает одну выходную ячейку на `FeatureDef`.
- `IndicatorFeatureVectorBuilder` описывает группы индикаторов с несколькими выходами.

Проверка, генерация имён, маршрутизация событий, сбор окон, связывание индексов и
создание экземпляров повторяются в модулях и построителях. Новый индикатор требует
согласованных правок нескольких match и путей создания.

Рабочее представление уже оптимизировано для одного индикатора с несколькими
окнами. Декларативная модель должна выражать то же, без перевода между определением
на ячейку и индикатором на группу.

Библиотека ещё не выпущена. Несовместимые изменения конфигурации, JSON, Rust и Python
допустимы ради меньшей и ясной архитектуры. Горячие пути расчёта/диспетчеризации
должны остаться без выделений памяти; конфигурация и компиляция могут выделять её.

<a id="decision"></a>

## Решение

Одна модель сгруппированного определения и один компилятор для всех интерфейсов.

Порядок создания:

```text
FeatureExtractorSpec or fluent builder
        |
        v
ordered ScopedIndicator values
        |
        v
validation and compilation
        |
        v
fixed-capacity IndicatorFeatureVector
```

Компилятор — деталь реализации. Публичный низкоуровневый интерфейс:

```rust
IndicatorFeatureVector::<F, V, M>::from_feature_extractor_spec(cells, &feature_extractor_spec)
```

`FeatureExtractor` с размером времени исполнения выбирает фиксированную ёмкость
и делегирует тому же интерфейсу. Цепочечный построитель создаёт переиспользуемый
`FeatureExtractorSpec`, не владея выходным хранилищем и отдельной иерархией
ожидающих признаков.

Совместимые обёртки старых построителей и JSON не сохраняются.

<a id="definition-model"></a>

## Модель определения

`FeatureExtractorSpec` — упорядоченная коллекция `ScopedIndicator`.

`ScopedIndicator` содержит:

- имя символа для индикатора с привязкой к символу;
- один `IndicatorSpec`;
- одно или несколько упорядоченных определений выходов в спецификации.

Определение представляет один рабочий индикатор. Выходы занимают непрерывный
`OutputRange` (начало и число). Выход `i` пишет в `span.start + i`; адаптеры не
хранят массивы произвольных индексов.

Порядок определений и выходов задаёт вызывающий код; компилятор не переставляет
ячейки. Совместимые определения автоматически не объединяются: повтор одной
идентичности ошибочен, окна нужно объединить в одном определении.

Идентичность включает:

- символ, если применим;
- тип индикатора;
- источник входа, если настраивается;
- длительность агрегации для интервальных индикаторов.

Выходные окна не входят в идентичность.

<a id="output-cardinality"></a>

## Число выходов

Группы SMA, EMA, временных SMA и OBV содержат упорядоченные списки окон.
Для одного выхода нужен список из одного элемента.

Каждая группа должна:

- содержать минимум один выход;
- не повторять длины окон;
- содержать не больше `MAX_OUTPUTS_PER_INDICATOR`, первоначально 16.

Временное число сделок пока имеет одно окно и выход; несколько окон отложены.

`FeatureExtractor` ограничен 128 выходными ячейками и 128 экземплярами индикаторов.
Статическая компиляция также проверяет фиксированные ёмкости вызывающего кода.

Размер хранилища точно равен числу выходов. Безымянные/неиспользуемые хвостовые
ячейки запрещены: длины имён и значений всегда равны.

<a id="value-sources"></a>

## Источники значений

Средние используют отдельный `ValueSource` вместо более широкого `EventKind`.
Начальные источники:

- `Price`;
- `Volume`;
- `TradePrice`;
- `TradeVolume`.

`ValueSource` задаёт соответствие поля события маршруту. Неподдерживаемые сочетания
непредставимы. Цена — значение по умолчанию цепочечного и Python-построителя;
сериализованные определения хранят источник явно.

OBV и число сделок имеют фиксированный вход сделок, без настройки источника.

<a id="timed-windows"></a>

## Временные окна

Временные SMA и OBV разделяют определение `TimeWindows`:

```rust
TimeWindows {
    aggregation: Duration,
    windows: Vec<Duration>,
}
```

Компиляция проверяет:

- агрегация не меньше миллисекунды;
- окно не меньше одной агрегации;
- окно точно кратно агрегации;
- преобразования и производные длительности помещаются в `i64` миллисекунд.

До создания экземпляра компилятор переводит проверенные длительности в периоды
интервалов. Те же правила действуют для единственного окна числа сделок.

<a id="generated-feature-names"></a>

## Генерируемые имена признаков

Произвольные пользовательские имена удаляются. Библиотека генерирует стабильные,
глобально уникальные канонические имена по структуре идентичности.

Разделённые двоеточиями сегменты содержат символ, источник, тип и параметры выхода:

```text
AAPL:price:sma:20
AAPL:trade_price:ema:10
AAPL:price:sma_timed:1000ms:60000ms
AAPL:trade:obv_timed:1000ms:60000ms
AAPL:trade:count_timed:1000ms:60000ms
clock:day_of_week
```

В символе экранируются `%` и `:`, чтобы разделители оставались однозначными.
Компиляция проверяет глобальную уникальность имён.

Псевдонимов нет; их можно добавить при конкретной потребности, оправдывающей API
и метаданные.

Глобальные имена включают символ, поэтому поиск выглядит так:

```rust
fn index_of(&self, canonical_name: &str) -> Option<usize>;
```

Ядро хранит имена один раз и отдаёт заимствованный срез без клонирования при каждом
вызове. Нескомпилированный `FeatureExtractorSpec` не предоставляет имён, а имеет
явные `indicator_count()` и `output_count()` вместо неоднозначного `len()`.

<a id="clock-features"></a>

## Признаки часов

Текущие признаки часов обновляются любым событием без фильтра символа, поэтому
моделируются глобальными определениями без символа.

`DayOfWeek` остаётся глобальным признаком.

`TimeSinceSessionOpen` переименовывается в `TimeSinceFirstEventOfDay`: он измеряет
время с первого события после локальной границы дня, не календарь биржи и не
настроенное открытие сессии.

Фиксированное смещение UTC:

- в пределах `-14h..=+14h`;
- с точностью до целой минуты.

Будущий календарный/символьный признак сессии проектируется отдельно с явными
фильтрами и календарной семантикой.

<a id="validation-and-errors"></a>

## Проверка и ошибки

Компилятор — единственный путь семантической проверки `FeatureExtractorSpec`.
Построители собирают определения и делегируют проверку компиляции.

Проверка прекращается при первой ошибке. Некорректное определение возвращает:

```rust
FimlError::InvalidIndicatorDefinition {
    index: usize,
    reason: String,
}
```

Причина содержит тип, символ при наличии, ошибочное поле и значение. Ошибки ёмкости
и времени остаются отдельными вариантами.

Отдельные низкоуровневые индикаторы публичны и проверяют свои инварианты. Компилятор
делегирует им создание и дополняет ошибки контекстом определения.

Компиляция может использовать временный `Vec`, полностью создавая элементы перед
переносом в фиксированные массивы. Это исключает частично инициализированные
массивы и упрощает очистку при ошибке.

<a id="runtime-and-allocation-contract"></a>

## Рабочее исполнение и память

Конфигурация, JSON, генерация имён и компиляция могут выделять память.

Скомпилированный экстрактор заранее владеет всем хранилищем для:

- проверки порядка;
- маршрутизации;
- обновления состояния;
- записи всех выходных ячеек.

Обработка события и обновление значений не выделяют память на каждое событие.

Фиксированные массивы пока сохраняются. Замена на boxed-срезы отложена до
подтверждения производительности замерами диспетчеризации.

Адаптеры остаются конкретными (`SmaFeature`, `EmaFeature`, `ObvTimedFeature` и др.).
Небольшие примитивы вроде `OutputRange` и встраиваемого помощника записи могут быть
общими. Универсальной generic-обёртки признака не будет.

<a id="event-ordering"></a>

## Порядок событий

Ядро владеет одной глобальной неубывающей временной границей. Любое событие, даже
не используемое символьным индикатором, имеет время не меньше предыдущего успешно
обработанного события.

Python делегирует проверку ядру вместо отдельного глобального правила при
потоковом `HashMap` в ядре. Это убирает расхождения семантики, дублирование проверки
и возможные выделения памяти карты в горячем пути.

<a id="module-ownership"></a>

## Ответственность модулей

Слой признаков разделён по ответственности:

- `features/definition.rs`: `FeatureExtractorSpec`, `ScopedIndicator`,
  `IndicatorSpec`, `ValueSource`, `TimeWindows`, канонические имена.
- `features/builder.rs`: цепочечное создание определений.
- `features/compiler.rs`: проверка, диапазоны, маршрутизация, имена, создание.
- `features/indicator_vector.rs`: скомпилированное хранилище и диспетчеризация.
- `features/builtin/`: конкретные адаптеры событий к индикаторам.
- `indicators/`: только алгоритмы расчёта.

Расчётные модули не знают имён признаков, символов, маршрутов и выходных ячеек.

<a id="numerical-behavior"></a>

## Численное поведение

Архитектурное изменение сохраняет расчёты. В частности, прогрев SMA по отсчётам
не меняется, хотя его поведение и документация требуют отдельного решения.

<a id="implementation-sequence"></a>

## Порядок реализации

1. Добавить замеры диспетчеризации: один/групповые выходы, несколько символов и
   маршрутов, события времени.
2. Зафиксировать текущее численное поведение тестами.
3. Ввести групповые определения, имена, `ValueSource`, `TimeWindows`, `OutputRange`.
4. Ввести один компилятор с временным инициализированным хранилищем.
5. Перенести SMA/EMA, затем временные SMA/OBV, число сделок и глобальные часы.
6. Заменить параллельный построитель построителем `FeatureExtractorSpec`.
7. Перенести глобальный порядок в ядро и убрать дублирование Python.
8. Обновить примеры Rust, привязки/тесты Python, блокноты, JSON и документацию.
9. После стабилизации объединить тесты контракта кольцевых буферов и повторяющиеся
   помощники тестов чисел с плавающей точкой.

Каждая миграция удаляет старый путь в том же изменении. Между миграциями репозиторий
должен собираться и проходить тесты; длительного параллельного компилятора не будет.

<a id="consequences"></a>

## Последствия

- Один путь определения и компиляции нового индикатора.
- Публичные определения соответствуют оптимизированной группировке исполнения.
- Порядок и смежность выходов становятся явными инвариантами.
- Источники средних читаемы и типобезопасны.
- Имена и поиск детерминированы в Rust/Python.
- Убирается карта временных меток потоков при диспетчеризации.
- Создание проще для понимания и безопаснее при ошибках.
- Публичные интерфейсы Rust, Python, JSON несовместимо меняются.
- Построение/компиляция могут выделять память; диспетчеризация — нет.
- Сложность фиксированных ёмкостей сохраняется до обоснования замерами.

<a id="deferred-decisions"></a>

## Отложенные решения

- Несколько окон числа сделок с общим буфером интервалов.
- Семантика прогрева SMA по отсчётам, согласование документации и тестов качества модели.
- Сравнение фиксированных массивов с boxed-срезами на новых замерах.
- Псевдонимы признаков только при доказанной недостаточности канонических имён.
