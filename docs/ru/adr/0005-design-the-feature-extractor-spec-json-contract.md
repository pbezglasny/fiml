# ADR 0005: JSON-контракт спецификации вектора признаков

Статус: принято\
Дата: 2026-07-29

<a id="context"></a>

## Контекст

JSON `FeatureExtractorSpec` согласует обучение Python и применение Rust. Исходный
формат получался напрямую через derive Serde и раскрывал детали Rust: внешние
теги enum PascalCase, `Duration { secs, nanos }`, символы `null` глобальных признаков.

Нужна стабильная независимая от языка схема с одним каноническим порядком выходов:
он определяет столбцы вектора модели.

<a id="decision"></a>

## Решение

Совместимость со старым derive-форматом намеренно не сохраняется. Запись выдаёт
точную версию `1.1`, чтение принимает только её.

Верхний уровень:

```json
{
  "version": "1.1",
  "capacity": 128,
  "length": 100,
  "required_events": [],
  "checksum": "optional opaque metadata",
  "features": []
}
```

`features` содержит группы с обязательным нормализованным `symbol`; глобальные
используют `__global__`. В каждой группе непустой массив `indicators`.
Повтор нормализованных групп символов — ошибка.

`required_events` выводится из групп и содержит канонические уникальные входы
`{symbol, event}`. Несоответствие метаданных индикаторам отклоняется. Глобальные
`any_event` используют конкретный глобальный вход `time`; стакану нужны дельты и снимки.

Индикаторы имеют строгую общую оболочку с `kind`, `source`, применимым
`warmup_policy`, необязательными общими `options` и `outputs`. Пустые options
опускаются. Стандартный скалярный выход записывается без `outputs`; `id` записывается
только при отличии от детерминированного. Пустые массивы выходов запрещены.

Длительности — целые строки с `ms`, `s`, `m`, `h`; запись выбирает наибольшую
точную единицу. Смещения UTC принимают существующие формы Python и записываются
как `±HH:MM`.

Канонический порядок:

1. Требуемые события по нормализованному символу и имени события.
2. Глобальная группа.
3. Группы по нормализованному символу.
4. Индикаторы по имени, затем полям идентичности.
5. Выходы в заданном порядке окон.

Вход может быть неотсортирован; загрузка создаёт канонический `FeatureExtractorSpec`.

Развёрнутое число выходов равно `length`, `capacity` не меньше него. Хвост ёмкости —
резерв ширины модели, не активные признаки. `checksum` сохраняется без вычисления
и проверки. Пустая спецификация допустима, пустая группа — нет.

<a id="module-seam"></a>

## Граница модулей

Рабочие определения остаются плоской канонической коллекцией для компиляции.
Приватный `features/serde/serialization.rs` владеет иерархической внешней моделью.

Интерфейс — существующие `Serialize` и `Deserialize` для `FeatureExtractorSpec`.
Python делегирует им же. Группировка, сортировка, строгие поля, форматирование,
проверка версий и преобразование остаются приватными.

Сериализация проверяет внешний контракт и области действия. Компиляция экстрактора
остаётся единым семантическим валидатором окон, идентичностей, ёмкости и уникальности имён.

<a id="consequences"></a>

## Последствия

- JSON не раскрывает представление enum/`Duration` Rust.
- Rust и Python не могут получить разные сериализаторы.
- Канонический порядок независим от построителя и входного JSON.
- Хранилище индикаторов `FeatureExtractorSpec` приватно ради инварианта порядка.
- Старые артефакты разработки и документацию нужно перегенерировать.
- Новые верхнеуровневые параметры требуют осознанного решения о версии формата.
