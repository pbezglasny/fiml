# ADR 0008: Сериализация спецификации конвейера

Обновление (2026-10-22): текущий формат `4.0` использует индексированные узлы графа
и именованные выходы. [Контракт графа](../multiple_output.md) заменяет линейную
оболочку и конструкторы ниже. Граница сериализации прежняя: конфигурация, не живое
состояние. Далее записаны исторические версии и обоснования.

Статус: принято\
Дата: 2026-09-02

<a id="context"></a>

## Контекст

`FeatureExtractorSpec` версионирует исходное извлечение, но модель потребляет
упорядоченный результат последующих преобразований. Раздельное сохранение
извлечения и обученной предобработки создаёт риск расхождения обучения/применения.

Живой `Pipeline` также содержит состояние экстрактора, скомпилированные индексы
и векторы вызывающего кода. Это не воспроизводимая конфигурация модели и не должно
входить в контракт хранения.

<a id="decision"></a>

## Решение

Граница сериализации — `PipelineSpec`. `Pipeline`, скомпилированные скалярные
операции и приватное внешнее представление `TransformerDefinition` не сериализуются.
Serde доступен только через существующую необязательную возможность `serde`.

Артефакт входа модели имеет собственную точную версию `1.0`, независимую от вложенной:

```json
{
  "version": "1.0",
  "checksum": "optional model metadata",
  "feature_extractor": {
    "version": "1.0",
    "capacity": 2,
    "length": 2,
    "features": []
  },
  "model_input": {
    "capacity": 2,
    "length": 2,
    "transformations": [
      {
        "type": "identity",
        "input": "raw_day",
        "output": "day"
      },
      {
        "type": "standard_scale",
        "input": "raw_sma",
        "output": "scaled_sma",
        "mean": 4.0,
        "scale": 2.0
      }
    ]
  }
}
```

`model_input` задаёт конечные размерности и преобразования. Они используют
стабильные ID, а не индексы. Авторский порядок сохраняется как порядок вектора
модели. Параметры стандартного масштабирования — JSON-числа, читаемые как `f64`.

Вложенный `FeatureExtractorSpec` использует канонический адаптер. Контрольные суммы
исходной и модельной спецификаций — независимые непрозрачные строки; любую можно
опустить, библиотека их не вычисляет и не проверяет.

Чтение строго отклоняет неизвестные версии/поля/типы, недостающие поля, явные `null`
в необязательных полях и несовпадения длины/ёмкости. После структурной проверки
вызывается `PipelineSpec::with_metadata` — единая семантическая проверка входных/
выходных ID и обученных числовых параметров.

<a id="consequences"></a>

## Последствия

- Один артефакт воспроизводимо описывает извлечение и конечный вход модели.
- Сериализация выделяет память только при конфигурации, не меняя путь событий.
- Рабочее состояние и векторы вызывающего кода из артефакта не восстанавливаются.
- `FeatureExtractorSpec` по-прежнему сериализуется независимо.
- Версии модельного и исходного форматов развиваются независимо.
- Привязки Python и сохранение рабочего состояния вне этого решения.

<a id="amendment-fitted-vector-stages-2026-09-09-issue-93"></a>

## Дополнение: обученные векторные этапы (2026-09-09, задача #93)

Запись выдаёт `2.0` с обязательным `model_input.stages` (может быть пустым).
Строгий `1.0` читается, но не должен содержать stages. Вложенный экстрактор остаётся
`1.0`. Пример выше исторический; [канонический пример](../../example_of_store_definition.json)
использует текущий формат.

Скалярные преобразования задают базовую раскладку. Обученный этап читает всю
предыдущую активную раскладку. Масштабирования хранят эффективные средние/масштабы;
PCA — строки компонент, средние, ID и эффективные делители отбеливания.
Конечная длина определяется последним этапом независимо от базовой/временной ширины.
См. [контракт обученных этапов](../pipeline_transformer.md).

`PipelineSpec::with_stages` — общий семантический валидатор; `with_metadata`
делегирует без этапов. Python хранит шаблоны sklearn отдельно и публикует
спецификацию только после успешного обучения/компиляции. Состояние событий и
обучающие данные по-прежнему не экспортируются. Поддерживаемые здесь потребители
serde_json включают `float_roundtrip` для точного сохранения `f64`; другим
потребителям Rust также следует включить его.
