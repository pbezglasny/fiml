# ADR 0001: Сделки как граница высокоуровневого DataFrame API Python

> Уточнение порядка (2026-09-08): порядок и продвижение временных окон теперь
> определяются отдельно для символа по всем видам событий. Глобальные тики Time
> влияют только на GLOBAL; календарные признаки следуют максимальной принятой
> метке. Это заменяет формулировки о глобальном порядке/истечении ниже.

Статус: принято\
Дата: 2026-07-14

<a id="context"></a>

## Контекст

API Python принимал бары и сделки через переключатель `source` и требовал повторять
все соответствия столбцов. Текущий сценарий блокнота имеет конкретную схему сделок
и требует один готовый для ML снимок на сделку. Несколько высокоуровневых форм
источника усложняют проверку, выравнивание и документацию сверх подтверждённой нужды.

<a id="decision"></a>

## Решение

`FeatureExtractor.compute_features` принимает только pandas DataFrame сделок.
Настраиваемые соответствия столбцов имеют значения по умолчанию `symbol`, `ts`,
`price`, `volume`; результат — копии метаданных символа/времени и полный снимок
вектора на каждую входную сделку.

Файловый ввод-вывод остаётся вне `fiml`. Бары и другие виды событий доступны через
низкоуровневые `update`, `transform`.

Экстрактор Python требует единый глобальный неубывающий порядок меток во всех
изменяющих методах. Вызовы полностью проверяются до обработки. Вычисления —
`float64`; настройка `output_dtype` до обработки выбирает выходы `float32`/`float64`.

<a id="consequences"></a>

## Последствия

- Обычный вызов в блокноте: `extractor.compute_features(trades)`.
- Соответствие входа и выхода имеет единый явный контракт.
- DataFrame баров можно позднее спроектировать отдельно, без скрытого режима `source`.
- Пользователь отвечает за загрузку, сортировку и сохранение данных.
- Строгая предварительная проверка использует временные массивы, чтобы ошибочный
  пакет не мог частично изменить экстрактор.
