# ADR 0006: Идентичность символов без учёта регистра

Статус: принято\
Дата: 2026-07-29

<a id="context"></a>

## Контекст

Канонические группы сортируются по символу и записывают его в нижнем регистре.
При нормализации только конфигурации экстрактор `btcusdt` не получал бы события
символа `BTCUSDT`.

Регистр — общее правило идентичности конфигурации, ввода событий, диспетчеризации,
имён признаков и дескрипторов Python, а не только сериализации.

<a id="decision"></a>

## Решение

Идентичность символов во всей библиотеке не учитывает регистр ASCII.
`symbols::intern` переводит заглавные ASCII в строчные до поиска/вставки.
Разрешённые и сериализованные символы используют канонический нижний регистр.

Построители Rust и `FeatureExtractorSpec::new` также нормализуют сохранённые строки.
Проверка дублей JSON выполняется после нормализации: группы `BTCUSDT` и `btcusdt`
ошибочны. Проверка идентичности индикаторов считает их одним символом.

Не-ASCII знаки не меняются. Финансовые символы трактуются как ASCII-идентификаторы;
зависимое от локали преобразование регистра вне контракта.

<a id="consequences"></a>

## Последствия

- Варианты регистра ASCII разрешаются в один `Symbol`.
- Сегменты символа в именах признаков строчные.
- Тесты, примеры и модели с заглавными символами сериализуются иначе.
- Нормализация оплачивается только при интернировании и определении признаков,
  не при обновлении индикаторов.
