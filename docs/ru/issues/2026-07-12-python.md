# Обзор привязок Python — проблемы и улучшения

Дата: 2026-07-12. Область: `crates/fiml-python` (PyO3), проверено по
`docs/specs/python.md`. Статусы: `open`, `in-progress`, `done`.

<a id="1-broken--stale-blockers"></a>

## 1. Сломанное / устаревшее (блокирует работу)

<a id="11-bindings-do-not-compile-after-the-core-rename--done"></a>

### 1.1 Привязки не собираются после переименования ядра — `done`

`crates/fiml-python/src/lib.rs:9` импортирует `DynIndicatorEngine`, `EngineSpec`,
а ядро экспортирует `FeatureExtractor`, `FeatureExtractorSpec` (§12.5/§12.6).
`from_spec` стал `from_feature_extractor_spec`. `cargo check -p fiml-python` даёт E0432.

<a id="12-stale-spec-json-key-in-examples-and-readme--done"></a>

### 1.2 Старый JSON-ключ `"spec"` в примерах и README — `done`

Поле `FeatureDef` переименовано `spec` → `indicator`, изменив ключ признака.
Старый ключ (ошибка загрузки даже после исправления 1.1) остаётся в:

- `crates/fiml-python/examples/quickstart.py` (словарь `SPEC`);
- `crates/fiml-python/README.md` (JSON-пример контракта);
- `crates/fiml/examples/spec_engine.rs` (`SPEC_JSON`).

<a id="13-naming-not-yet-aligned-with-spec-125126--done"></a>

### 1.3 Имена не согласованы с §12.5/§12.6 — `done`

Класс всё ещё `Engine` с `from_spec_json`. Цель: `FeatureExtractor` с
`FeatureExtractor.from_json` / созданием из `FeatureExtractorSpec`, обновить
`python/fiml/__init__.py`, quickstart, README, docstrings.

<a id="2-correctness"></a>

## 2. Корректность

<a id="21-warmup-rows-read-as-00--done"></a>

### 2.1 Прогрев читается как 0.0 — `done`

Ячейки начинаются с нуля и пишутся только при значении индикатора, поэтому строки
`transform` до прогрева содержат `0.0`, неотличимый от настоящего нуля (например OBV).
Модель молча учится на фиктивных нулях. Рекомендация — NaN. Варианты от дешёвого:

- NaN в снимке привязок с маской никогда не записанных ячеек;
- NaN при инициализации вектора ядра;
- число/маска строк прогрева рядом с матрицей.

Нужно решить до обучения на результатах `transform`/`compute_features`.

<a id="22-partial-state-mutation-when-transform-fails-mid-stream--done"></a>

### 2.2 Частичное изменение при ошибке `transform` — `done`

Если строка `i` ошибочна (нет поля вида, неизвестный символ), строки `0..i` уже
продвинули состояние без возможности это определить. Исправление: дешёвый
предварительный проход `kind`, проверяющий нужные поля и диапазоны символов,
для атомарности.

<a id="3-missing-api-spec-gaps"></a>

## 3. Недостающий API

<a id="31-no-featureextractorspec-builder--users-hand-write-serde-json--done"></a>

### 3.1 Нет построителя FeatureExtractorSpec — JSON serde пишется вручную — `done`

`from_spec_json` заставляет писать теги enum Rust и `Duration` как
`{"secs": ..., "nanos": ...}`. §3b требует pyclass `FeatureExtractorSpec` с
`.sma()`, `.ema()`, `.sma_timed()`, `.obv_timed()`, `.trade_count_timed()`,
`.day_of_week()`, `.time_since_session_open()`, `to_json()`/`from_json()`.
JSON остаётся артефактом рядом с моделью, но не пишется людьми. Наиболее полезное улучшение.

Ядро отличается от `tz: str` спецификации: Rust
`TimeSinceSessionOpen { utc_offset_millis: i64 }` избегает зависимости от базы IANA
(минимум зависимостей AGENTS.md). Python должен переводить `tz="UTC"` в `0`.

<a id="32-no-high-level-compute_featuresdf---done"></a>

### 3.2 Нет высокоуровневого `compute_features(df, ...)` — `done`

Реализован контракт только сделок из `docs/specs/python2027-07-14.md`: настраиваемые
столбцы, канонические значения по умолчанию, строгие миллисекунды, копии метаданных,
снимок на сделку. `transform` остаётся низким уровнем для смешанных потоков/баров.

<a id="4-performance--ergonomics"></a>

## 4. Производительность / удобство

<a id="41-values-allocates-per-call--done"></a>

### 4.1 `values()` выделяет память при каждом вызове — `done`

Возвращает `Vec<f64>` → список Python: выделение на событие в потоке.
Возвращать NumPy напрямую либо добавить update в пользовательский буфер
(соответствует минимизации выделений AGENTS.md).

<a id="42-gil-held-for-the-whole-transform-loop--open-low-priority"></a>

### 4.2 GIL удерживается весь цикл `transform` — `open`, низкий приоритет

Для больших таблиц `py.allow_threads` вокруг обработки позволил бы другим потокам
Python работать. Требует перестройки (заимствования NumPy связаны с GIL).
Для однопоточного ML не срочно.

<a id="43-no-reset--open-needs-core-support"></a>

### 4.3 Нет `reset()` — `open`, нужна поддержка ядра

Повторный бэктест требует разбирать JSON заново. Сброс ядра через привязки избавил
бы от этого. Изменение ядра — согласовать перед реализацией.

<a id="44-cosmetics--open"></a>

### 4.4 Косметика — `open`

- `symbol()` возвращает `usize`, столбец symbol имеет dtype `i64`.
- pyo3/numpy закреплены на 0.23, отстают на несколько выпусков; обновить при случае.

<a id="considered-and-rejected"></a>

## Рассмотрено и отклонено

Методы по видам (`transform_prices(...)`, `transform_trades(...)`) убрали бы
построчные `Option` и `kind`, но разрушили бы единый перемежающийся поток в реальном
порядке, от которого зависит совпадение. Сохранить
`(kind, symbol, timestamp, payload...)` под `compute_features`.
