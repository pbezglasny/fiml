# Обзор кодовой базы — 2026-09-05

Обзор ядра Rust и привязок Python: корректность, выделения памяти и совпадение
векторов. Воспроизведено семь проблем. Реализация в рамках обзора не менялась.

<a id="1-p1--non-finite-input-permanently-poisons-indicators--resolved"></a>

## 1. P1 — Неконечный вход навсегда портит индикаторы — исправлено

**Место:** [FeatureExtractor::handle_event](../../../crates/fiml/src/features/feature_extractor.rs)
и `build_event` / `require` общего исполнения Python в
[lib.rs](../../../crates/fiml-python/src/lib.rs).

Раньше Rust и Python `update`/`transform` принимали NaN/бесконечность без проверки.
Инкрементальное состояние становилось неконечным и не восстанавливалось после
ухода отсчёта. DataFrame `compute_features` уже проверял конечность: пути различались.

**Исходное воспроизведение:** цены `100, NaN, 102, 103, 104` в SMA периода 2 с
возрастающим временем. Все события успешны, итог NaN вместо среднего последних
двух цен `103.5`. Воспроизведено в Rust и низкоуровневом Python.

**Влияние:** плохой тик молча выключает индикатор до конца жизни экземпляра.
NaN неотличим от прогрева/пропуска.

**Исправление (2026-09-05):** `Event::validate_finite_values` отклоняет NaN и
±бесконечность типизированной ошибкой без выделений
`InvalidArgumentError::NonFiniteEventValue { field: EventField }`.
Проверяются отдельные цена/объём и оба поля сделки, сначала цена. Экстрактор
проверяет после порядка времени и до изменений, включая неподписанные символы.
Конвейеры наследуют проверку. Общий Python `build_event` проверяет до пакета,
сохраняя `ValueError` и `row N:`.

Отклонение сохраняет значения, исходные/конечные снимки, временное состояние и
границу. Первый отклонённый вход не блокирует dtype Python. Конечные нули/отрицательные
на низком уровне допустимы, лишние поля игнорируются, DataFrame требует положительные.
Отдельные индикаторы требуют конечных входов от вызывающего кода; восстановление
уже испорченного состояния и переполнение конечных входов вне исправления.

**Проверка:** все четыре поля с NaN/обеими бесконечностями, сохранение состояния
подписанных/неподписанных символов, атомарность пакетов, блокировка dtype, совпадение
с новым экземпляром. SMA после отклонения NaN и приёма `102, 103, 104` даёт `103.5`.
Счётчик подтверждает отсутствие выделений принятия/отклонения без форматирования
ошибки в измеряемой секции.

- `cargo test --workspace --all-targets --all-features` — успешно.
- `cargo test --workspace --all-features --doc` — успешно.
- Python с пересобранными привязками — **178 тестов**.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings` — успешно.
- `cargo fmt --all -- --check` — успешно.

Исправляет также §1.4 [июльского обзора](2026-07-25-claude-review.md).

<a id="2-p1--exceeding-the-symbol-limit-poisons-the-global-interner--resolved"></a>

## 2. P1 — Превышение числа символов портит глобальный интернер — исправлено

**Место:** `SymbolInterner::intern`, `symbols::intern`, `symbols::resolve` в
[symbols.rs](../../../crates/fiml/src/symbols.rs).

Интернер процесса допускает 512 символов с GLOBAL. Раньше новый сверх лимита
вызывал assert под глобальным mutex. Раскрутка стека отравляла mutex, дальнейшие
операции вызывали `lock().unwrap()`.

**Воспроизведение:** в отдельном процессе интернировать 511 рыночных символов,
попытаться 512-й, поймать панику, затем интернировать старое имя/разрешить старый
символ: обе операции тоже паникуют.

**Влияние:** лимит общий для экстракторов/загрузок. Одно превышение ломает будущие
операции, включая ранее корректные символы.

**Исправление (2026-09-06):** ёмкость проверяется до вставки, возвращается
`LimitExceeded` с `LimitTarget::Symbols`. Старые имена ищутся первыми, поэтому
варианты регистра ASCII и GLOBAL работают на пределе. Повторные ошибки не портят mutex.

`Symbol::new`, `symbols::intern` теперь возвращают `fiml::Result<Symbol>`;
строковые `From` заменены `TryFrom`. Rust обрабатывает/передаёт ошибку, например
`Symbol::new(name)?`; примеры/тесты перенесены. Загрузка символа/спецификации и
Python-построители/регистрация передают ошибку (`ValueError`) без изменения
спецификации, дескрипторов и состояния. Ёмкость 512 с GLOBAL прежняя, удаление
экземпляров имена не освобождает.

**Проверка:** отдельный Rust-процесс заполняет интернер, проверяет все строковые
конструкторы, загрузку, повторные ошибки, поиск/разрешение/форматирование старых
имён и дальнейшие события. Подпроцесс Python покрывает шесть символьных
построителей, оба runtime, загрузку исходных/модельных spec/runtime JSON,
включая успешное повторное использование после ошибки.

- `cargo test --workspace --all-targets --all-features -q` — успешно.
- `cargo test -p fiml --no-default-features --test symbol_capacity -q` — успешно.
- Python с пересобранными привязками — **179 тестов**.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings` — успешно.
- `cargo fmt --all -- --check` — успешно.

<a id="3-p1--extractor-construction-paths-disagree-about-missing-values--resolved"></a>

## 3. P1 — Пути создания расходятся в пропусках — исправлено

**Место:** `FeatureExtractorBuilder::build` в
[feature_extractor_builder.rs](../../../crates/fiml/src/features/feature_extractor_builder.rs)
и `FeatureExtractorSpec::build` в
[feature_extractor_spec.rs](../../../crates/fiml/src/features/serde/feature_extractor_spec.rs).

Прямой построитель сохранял начальное содержимое вектора (встроенные создают нули).
Спецификация сбрасывала все ячейки в NaN, включая резерв.

**Воспроизведение:** одинаковые SMA периода 2 с полным окном через построитель и
спецификацию; событие времени до цены. Прямой путь даёт `[0.0]`, spec — `[NaN]`.

**Влияние:** одинаковые определения дают разные пропуски по пути создания.
Прямой Rust расходится с Python-spec, нарушая прогрев; старые пользовательские
значения тоже могут оставаться до первой записи.

**Исправление (2026-09-06):** цикл NaN перенесён из spec в общий
`FeatureExtractor::new`. Оба пути сбрасывают все ячейки ровно раз, включая резерв
и старые значения, при создании после проверки. Обработка событий/расчёты и
сигнатуры ввода прежние.

**Проверка:** регрессия падала раньше, проходит теперь. Оба пути, нулевое/старое
хранилище, активные/резервные ячейки, начальные снимки, посторонние время/объём,
обе политики. SMA после `10, 20` даёт `15.0`, резерв NaN.

- `cargo test --workspace --all-targets --all-features -q` — успешно.
- Python с пересобранными привязками — **179 тестов**.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings` — успешно.
- `cargo fmt --all -- --check` — успешно.

<a id="4-p2--valid-sliced-dataframes-fail-the-contiguous-array-requirement"></a>

## 4. P2 — Корректные срезы DataFrame нарушают требование непрерывности

**Место:** `_compute_features` в
[__init__.py](../../../crates/fiml-python/python/fiml/__init__.py) и
`RuntimeDriver::transform` в [lib.rs](../../../crates/fiml-python/src/lib.rs).

Обёртка получает время через `to_numpy(dtype=np.int64, copy=False)`, сохраняя
возможное представление с шагом. Массивы числовых полей также могут быть
неконтигуальными, а Rust `as_slice()` требует непрерывный массив.

**Воспроизведение:** корректный хронологический DataFrame на шесть сделок.
`compute_features(df)` успешен, `compute_features(df.iloc[::2])` вызывает:

```text
TypeError: The given array is not contiguous
```

Шаг временного массива — 16 байт вместо 8.

**Влияние:** обычный pandas-срез неожиданно не воспроизводится. Общая обёртка
затрагивает экстракторы и конвейеры.

**Предложение:** `np.ascontiguousarray` на границе DataFrame, копирует лишь при необходимости.

<a id="5-p2--timed-sma-accepts-late-windows-without-initializing-their-history"></a>

## 5. P2 — Временная SMA принимает поздние окна без их истории

**Место:** `SimpleMovingAverageTimed::add_window_with_periods` в
[indicator.rs](../../../crates/fiml/src/indicators/averages/sma/indicator.rs).

В отличие от SMA по отсчётам и временного OBV, добавление окна после данных не
запрещено. Новое окно имеет пустую сумму/число интервалов при уже имеющейся общей истории.

**Воспроизведение:** агрегация 1 с, `FirstValue`:

1. Добавить окно 2 периода.
2. Значение `100` в `0`.
3. Добавить ещё окно 2 — успешно.
4. Значение `200` в `1000`.

Старое окно даёт `150`, идентичное новое — `200`.

**Влияние:** успешный публичный вызов создаёт окно без доступной истории,
расходящееся с идентичным существующим.

**Предложение:** запрещать добавление после данных через `WindowAddedAfterData`,
как в других оконных индикаторах.

<a id="6-p2--order-book-dispatch-allocates-on-the-event-processing-path"></a>

## 6. P2 — Обработка стакана выделяет память на пути событий

**Место:** `BookSide::update_level` в
[book_side.rs](../../../crates/fiml/src/order_book/book_side.rs).

Уровни в `BTreeMap`: вставка может выделять узлы внутри принятого
`FeatureExtractor::handle_event`. Замена снимка очищает/воссоздаёт карты.
Это не соответствует документированной границе без выделений.

**Воспроизведение:** настроить стакан, пустой снимок, заранее создать дельту с
новым bid; включить счётчик. Обработка готовой дельты выделяет память в куче один раз.

**Влияние:** ввод стакана вызывает аллокатор вопреки гарантии. Текущие тесты
выделений конвейера путь не покрывают.

**Предложение:** если гарантия включает стакан, ограниченное заранее выделенное
хранилище и тесты. Иначе явно сузить гарантию до поддерживаемых путей.

<a id="7-p3--extreme-timestamps-overflow-timed-indicator-arithmetic"></a>

## 7. P3 — Крайние метки переполняют временную арифметику

**Место:** `bucket_start` и истечение в
[SMA](../../../crates/fiml/src/indicators/averages/sma/indicator.rs),
[OBV](../../../crates/fiml/src/indicators/volume/obv/indicator.rs),
[числе сделок](../../../crates/fiml/src/indicators/counts/trade_count.rs).

Начало интервала вычитает неотрицательный остаток прямо из `i64`.
Около `i64::MIN` математическое начало вне диапазона. Истечение добавляет
длительность прямо к метке, допуская переполнение верхней границы.

**Воспроизведение:** временная SMA с агрегацией 1 с, обновление в `i64::MIN`.
Debug паникует при вычислении начала.

**Влияние:** крайние, но представимые входы вызывают панику или перенос без
проверок переполнения. Это край диапазона, не обычные рыночные метки.

**Предложение:** определить/проверять границы до изменения либо расширить
промежуточную арифметику выравнивания/истечения.
