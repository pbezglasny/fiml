# Средние по отсчётам — преобразования конвейера

Версия JSON экстрактора теперь `2.0`, конвейера — `4.0`. Старые версии отклоняются.
Пересоздайте и экспортируйте конфигурации; автоматической конвертации нет.
Отдельные калькуляторы и функции SMA/EMA сохранены. Временная SMA, доходности,
волатильность и индикаторы сделок остаются признаками экстрактора.

Замените каждое определение SMA/EMA по отсчётам исходным полем и преобразованием
конвейера. Используйте одно поле для всех окон одного символа и источника.
Для сохранения имён столбцов модели задайте преобразованию прежний итоговый ID.
Исходные раскладки и ID меняются.

```python
import fiml

raw = fiml.FeatureExtractorSpec().field("BTCUSDT", source="trade_price", id="price")
stage = (fiml.ScalarStage()
        .sma("price", window=20, output="sma20")
        .ema("price", window=10, output="ema10"))
spec = fiml.PipelineSpec(raw)
spec.output("model", spec.add(spec.root(), stage))
pipeline = spec.build()
```

`field(symbol, *, source="price", id=None)` поддерживает `price`, `volume`,
`trade_price`, `trade_volume`. Начинается с NaN и сохраняет последнее подходящее
значение между наблюдениями. Rust использует `FeatureKey::Field { symbol, field }`.

`ScalarStage` предоставляет
`sma(input, *, window, warmup=WarmupPolicy.FULL_WINDOW, output=None)` и `ema(...)`.
Без `output` сохраняется входной ID. Rust использует `TransformerDefinition::sma`
и `::ema` с входным/выходным ID, окном и политикой прогрева. Окна положительны;
ограничение лага 10 000 здесь не действует. До 16 совместимых выходов разделяют
состояние внутри этапа по операции, входу и политике прогрева. SMA выделяет один
буфер истории по максимальному окну.

Определения одного скалярного этапа читают одну предыдущую раскладку.
Для композиции добавляйте последовательные этапы:

```python
spec = fiml.PipelineSpec(raw)
scaled = spec.add(spec.root(), fiml.ScalarStage().standard_scale("price", mean=100.0, scale=10.0))
smoothed = spec.add(scaled, fiml.ScalarStage().sma("price", window=20))
lagged = spec.add(smoothed, fiml.ScalarStage().lagged("price", lag_window=1))
spec.output("model", lagged)
```

Признаки стакана можно сглаживать напрямую: выберите ID из
`raw.order_book_imbalance(...)`, используйте как вход EMA, затем добавьте лаг.

Средние продвигаются только на наблюдаемых конечных входах. Повторные равные
значения считаются наблюдениями. Наблюдаемый NaN или бесконечность публикует NaN,
сохраняя конечную историю; следующее конечное наблюдение продолжает её.
Прогрев считает конечные наблюдения. Без наблюдения видимый выход, включая NaN,
сохраняется.

Флаги наблюдения следуют фактическим записям экстрактора. Буферизованные или
игнорируемые обновления стакана не дают наблюдения; синхронизация наблюдает
опубликованное состояние один раз. Тождественное преобразование, масштабирование,
отбор, обученные столбцовые преобразования, заполнения и индикаторы пропусков
наследуют флаги источника. PCA наблюдает все компоненты, когда наблюдается любой
вход, используя последние остальные значения. Лаг остаётся событийным и наблюдает
каждое принятое событие, включая прогрев. Отклонённые события не запускают этапы.

История, видимые выходы и флаги выделяются при создании и остаются приватным
состоянием. JSON содержит конфигурацию и обученные параметры; загрузка и сброс
начинают с пустой истории. Обучение и применение Python воспроизводят события
через Rust. Исключённые маской обучения строки тоже продвигают историю.
