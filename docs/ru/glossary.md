# Глоссарий

Термины библиотеки Rust, привязок Python и JSON-формата спецификации вектора.
Точные идентификаторы показаны как `snake_case` или `UpperCamelCase`.

<a id="core-concepts"></a>

## Основные понятия

<a id="canonical-feature-name"></a>

### Каноническое имя признака

Стабильное глобально уникальное имя [ячейки](#feature-cell), генерируемое при
компиляции. Сегменты через двоеточие описывают область, вход, индикатор и параметры,
например `field:symbol=7:btcusdt:source=field.trade_price`. Rust `FeatureDefinition`
и Python `field(..., id=...)` позволяют явные ID; скалярные преобразования задают
свои выходные ID независимо.

<a id="canonical-order"></a>

### Канонический порядок

Детерминированный порядок компиляции/сериализации: глобальная область, нормализованный
символ, имя индикатора, идентичность, авторский порядок окон. Именно он, а не
порядок построителя/JSON, определяет позиции ячеек.

<a id="feature-cell"></a>

### Ячейка признака

Один числовой вход модели в [векторе](#feature-vector). Индикатор может владеть
несколькими соседними ячейками: по одной на окно. `output_count` и `n_features`
Rust/Python считают ячейки, не экземпляры индикаторов.

В коде также используются *output* и *output cell*.

<a id="feature-extractor"></a>

### Экстрактор признаков

Скомпилированный движок с состоянием: принимает упорядоченный поток, поддерживает
текущий вектор. `FeatureExtractor` строится из спецификации вектора.

<a id="feature-row"></a>

### Строка признаков

Копия полного вектора после события. Пакетный Python возвращает строку на событие
или сделку. *Снимок* и *снимок вектора признаков* — синонимы.

<a id="feature-vector-spec"></a>

### Спецификация вектора признаков

Полное версионированное определение для создания экстрактора. `FeatureExtractorSpec`
содержит канонически упорядоченные определения и является общим артефактом обучения
Python и применения Rust.

<a id="feature-vector"></a>

### Вектор признаков

Упорядоченные числовые ячейки текущего состояния. `values()` читает их,
`feature_names()` описывает в том же порядке. Также *выходной вектор*, *текущие
значения*; копия на событии — [строка признаков](#feature-row).

<a id="indicator"></a>

### Индикатор

Расчёт, принимающий выбранные события и хранящий состояние для одной или нескольких
ячеек. Термин обозначает расчёт в целом либо, когда важно:

- [определение индикатора](#indicator-definition) — пользовательскую конфигурацию;
- [спецификацию индикатора](#indicator-specification) — вид и параметры;
- [рабочий экземпляр](#runtime-indicator-instance) — состояние расчёта.

Некоторые внутренние части Rust называют адаптер индикатора *feature*.
Не путать с ячейкой признака.

<a id="indicator-definition"></a>

### Определение индикатора

Пользовательская конфигурация `ScopedIndicator`: необязательная область символа
и одна спецификация. Может создавать несколько соседних ячеек.

<a id="indicator-identity"></a>

### Идентичность индикатора

Поля, различающие экземпляры независимо от окон: область, вид, применимые источник,
агрегация, UTC-смещение. Повтор идентичности ошибочен; окна нужно сгруппировать.

<a id="indicator-specification"></a>

### Спецификация индикатора

Структурированные вид и параметры `IndicatorSpec` без области символа/глобальной
области, хранящейся в `ScopedIndicator`. Обычное сокращение — *indicator spec*.

<a id="runtime-indicator-instance"></a>

### Рабочий экземпляр индикатора

Скомпилированный расчёт с состоянием из одного определения. Может обновлять несколько
ячеек, поэтому числа индикаторов и выходов различаются.

<a id="events-inputs-and-scope"></a>

## События, входы и область действия

<a id="event"></a>

### Событие

Один вход с меткой времени — тегированный enum `Event`: цена, объём, сделка,
стакан, время. Содержит соответствующие данные `*Update`.

Рыночные наблюдения также называются *тиками*, *обновлениями*, *входящими
изменениями*. Строго событие — оболочка с тегом, update — данные конкретного вида.

<a id="event-kind"></a>

### Вид события

Тег маршрутизации `EventKind`: `Price`, `Volume`, `Trade`, `OrderBook`, `Time`.
Индикаторы подписаны на один вид, кроме глобальных часов, наблюдающих любое событие
не раньше максимальной принятой метки. Временные индикаторы наблюдают все виды
своего символа.

<a id="event-time-watermark"></a>

### Граница времени событий

Последнее принятое время символа: `last_timestamp_for_symbol(Symbol)` Rust.
Знаковые 64-битные миллисекунды эпохи не убывают внутри символа по всем видам.
Его окна продвигаются только его событиями. `Event::Time` принадлежит
`Symbol::GLOBAL`, не продвигает другие символы. `last_timestamp()` показывает
последнее поступление и может уменьшаться между символами.

<a id="global-scope"></a>

### Глобальная область

Область индикатора без рыночного символа. Сейчас это часы, но *глобальный*
описывает область, а *часы* — поведение.

<a id="order-book-event"></a>

### Событие стакана

Событие с символом, bid, ask и временем. Поддерживается Rust и низкоуровневым Python,
хотя ни один текущий встроенный индикатор на него не подписан.

<a id="symbol"></a>

### Символ

Идентичность рыночного инструмента. Регистр ASCII не учитывается: интернирование,
конфигурация, сериализация и имена переводят заглавные ASCII в строчные.
Не-ASCII не меняется.

Интернированный Rust `Symbol` — дешёвый идентификатор. Python низкого уровня
использует локальный целый *дескриптор символа*, чтобы не хранить строку на событие.
*Ticker* встречается лишь как пример пользовательского имени столбца, не отдельное понятие.

<a id="symbol-scope"></a>

### Область символа

Индикатор потребляет события одного нормализованного символа. Такое определение
должно содержать непустой символ.

<a id="trade-side"></a>

### Сторона сделки

Классификация агрессора. Покупка даёт положительный вклад в CVD, продажа —
отрицательный; неклассифицированная сделка без стороны игнорируется CVD.

Python использует правильное написание `SIDE_AGGRESSOR_BUY`, `SIDE_AGGRESSOR_SELL`.
Текущие публичные варианты Rust содержат опечатку: `AgressorBuy`, `AgressorSell`.

<a id="value-source"></a>

### Источник значения

Числовое поле среднего (`ValueSource`): значение цены, объёма, цена/объём сделки.
В JSON — `price`, `volume`, `trade_price`, `trade_volume`.

<a id="windows-aggregation-and-readiness"></a>

## Окна, агрегация и готовность

<a id="aggregation-bucket"></a>

### Интервал агрегации

Интервал фиксированной длительности для группировки подходящих входов временного
индикатора. `aggregation` — его длительность; *aggregation duration* и *bucket
duration* обозначают одну настроенную величину.

<a id="readiness"></a>

### Готовность

Накоплена ли история по политике прогрева. Окна готовы независимо.
Готовность не равна доступности значения: у готовой временной SMA окно может быть пустым.

<a id="sample-window"></a>

### Окно по отсчётам

Скользящий горизонт в подходящих входных отсчётах. Положительная целая длина также
называется *периодом* в отдельных индикаторах и реализации. В публичной конфигурации
канонический термин — *окно*.

<a id="time-window"></a>

### Временное окно

Скользящий горизонт по времени событий из одного или нескольких интервалов.
Длительность не меньше агрегации и точно кратна ей. *Timed window* и
*time-based window* — то же понятие.

<a id="unavailable-value"></a>

### Недоступное значение

Выход без текущего числа из-за неготовности или отсутствия входа у готового
индикатора. Ячейки с плавающей точкой используют IEEE NaN.

<a id="warm-up"></a>

### Прогрев

Период до готовности выхода. `WarmupPolicy::FirstValue` открывает все выходы после
первого подходящего входа. `WarmupPolicy::FullWindow` скрывает каждый до полного
окна по отсчётам/времени. В идентификаторах используется *warmup*, в английской
прозе предпочтительно *warm-up*.

<a id="window"></a>

### Окно

Скользящая история для одного выхода: [по отсчётам](#sample-window) или
[по времени](#time-window). Каждое окно группы владеет соседней ячейкой.

<a id="built-in-indicators"></a>

## Встроенные индикаторы

<a id="cumulative-volume-delta-cvd"></a>

### Накопленная дельта объёма (CVD)

Скользящая сумма классифицированных объёмов: покупки агрессора положительны,
продажи отрицательны. Текущий CVD использует отсчёты и игнорирует сделки без стороны.

<a id="day-of-week"></a>

### День недели

Глобальные часы `day_of_week` по времени любого события: `0` — воскресенье,
`6` — суббота.

<a id="exponential-moving-average-ema"></a>

### Экспоненциальная скользящая средняя (EMA)

Средняя с экспоненциально большим весом новых входов. Период окна определяет
множитель сглаживания. Начальное состояние — первое подходящее значение.

<a id="simple-moving-average-sma"></a>

### Простая скользящая средняя (SMA)

Среднее арифметическое подходящих значений скользящего окна по отсчётам.

<a id="time-since-first-event-of-day"></a>

### Время с первого события дня

Глобальный `time_since_first_event_of_day` выдаёт миллисекунды с первого события
после локальной границы дня с фиксированным смещением.

<a id="timed-on-balance-volume-timed-obv"></a>

### Временной балансовый объём (OBV)

`obv_timed` агрегирует объёмы сделок во временные интервалы и назначает знак по
движению цены между интервалами.

<a id="timed-simple-moving-average-timed-sma"></a>

### Временная простая скользящая средняя (SMA)

`sma_timed` усредняет значения в фиксированных интервалах агрегации, сохраняемых
для одного или нескольких временных окон.

<a id="timed-trade-count"></a>

### Временное число сделок

Число сделок в скользящем временном окне с фиксированными интервалами.
Имя построителя и JSON — `trade_count_timed`.

<a id="timed-trade-volume"></a>

### Временной объём сделок

Сумма объёмов в одном или нескольких временных окнах с фиксированными интервалами.
Имя построителя и JSON — `trade_volume_timed`.

<a id="timed-vwap"></a>

### Временной VWAP

Сумма произведений цены и объёма, делённая на общий объём в одном/нескольких
временных окнах. `vwap_timed` недоступен при прогреве или без сделок в окне.

<a id="serialization-and-contributor-concepts"></a>

## Сериализация и понятия для участников

<a id="feature-group"></a>

### Группа признаков

Группа определений JSON с общей глобальной областью или нормализованным символом.
Рабочие определения плоские; на область допускается одна сериализованная группа.

В диспетчеризации Rust *feature group*/*dispatch group* также означает набор
рабочих признаков одного вида событий (или любых событий). Это другое понятие.

<a id="feature-vector-spec-format-version"></a>

### Версия формата спецификации

Версия сериализованного контракта независима от crate Rust и пакета Python.
Экстракторы пишут/читают `2.0`, конвейеры — `3.0`. Старым артефактам нужна явная
[миграция](sample-average-migration.md).

<a id="parity-artifact"></a>

### Артефакт согласованности

Сериализованная спецификация, сохранённая с моделью и загружаемая обучением Python
и применением Rust. Для совпадения нужны одинаковые спецификации и упорядоченные потоки.

<a id="semantic-validation"></a>

### Семантическая проверка

Проверка при компиляции: правила окон, уникальность идентичности, ёмкость,
уникальность генерируемых имён.

<a id="serialization-module"></a>

### Модуль сериализации

Приватный Rust-модуль преобразует иерархический JSON в плоские рабочие определения
и обратно. Публичный интерфейс — сериализация/десериализация `FeatureExtractorSpec`.

<a id="structural-validation"></a>

### Структурная проверка

Проверка однозначного преобразования JSON: форма полей, версия, синтаксис скаляров,
уникальность групп, область действия.
