# Несколько выходов конвейера

Конвейер владеет одним экстрактором и графом этапов, в который можно только добавлять
узлы. Этап читает один родительский вектор и может питать несколько потомков.
Повторное использование дескриптора узла разделяет вычисления, параметры и историю.
Регистрация выхода открывает существующий узел, не создавая нового расчёта.

Решения и обоснования записаны в [multiple_output-arc.md](multiple_output-arc.md).
Слияния нескольких родителей, автоматическая дедупликация, изменение графа во время
работы, отдельные маски обучения выходов и повторное использование временных буферов
отложены.

<a id="python-authoring-and-results"></a>

## Создание и результаты в Python

```python
import fiml
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

raw = (fiml.FeatureExtractorSpec()
       .field("BTCUSDT", source="trade_price", id="price")
       .field("BTCUSDT", source="trade_volume", id="volume"))
spec = fiml.PipelineSpec(raw)
root = spec.root()
projected = spec.add(root, PCA(n_components=2))
scaled = spec.add(projected, StandardScaler())
selected = spec.add(projected, fiml.ScalarStage().identity("pc0"))
spec.output("model_a", scaled)
spec.output("model_b", selected)
spec.output("decision", root)
pipeline = spec.build()
```

`add(parent, stage)` принимает `ScalarStage`, поддерживаемый оцениватель sklearn
или числовой словарь в JSON-формате обученного этапа. Например, фиксированный PCA
содержит `type`, `outputs`, `mean`, `components`, `output_scale`. Добавление копирует
скалярные/числовые конфигурации и клонирует оцениватели как необученные описания.
Поздние изменения исходного объекта не влияют на построитель. Каждый `build()`
создаёт независимый снимок. Дескрипторы принадлежат создавшему их построителю.

Конвейер с описаниями оценивателей требует `fit()` до применения или экспорта.
Регистрируйте символы через `pipeline.symbol(name)` до подготовки массивов событий.

```python
# training_events and following_events are the usual named event arrays.
pipeline.fit(**training_events, fit_mask=training_rows)
model_a = pipeline.output("model_a")
batch = pipeline.transform(**following_events)
X_a = batch["model_a"]
X_b = batch["model_b"]
latest_a = model_a.values()
```

`transform`, `fit_transform`, `transform_order_book` возвращают словари в порядке
регистрации выходов, даже для одного выхода. Матрица содержит строку на событие и
только активные столбцы. `compute_features` возвращает соответствующий словарь
DataFrame. Пустой пакет даёт матрицы без строк с настроенной шириной.
Онлайн-`update` обновляет узлы без создания пакетных матриц.

`PipelineOutput.values()` возвращает независимый NumPy-снимок. `feature_names()`,
`n_features()`, `active_feature_count()` описывают текущую обученную раскладку.
Дескриптор сохраняется после сброса/переобучения; ранее выданные массивы независимы.
У конвейера нет `values()` и выхода по умолчанию. `output_names()` перечисляет имена.

Имена выходов уникальны, непусты и не начинаются с `__reserved_`. Исполняемый
конвейер требует минимум один выход с минимум одним активным признаком. Несколько
имён могут указывать на один узел. ID локальны узлу; имена PCA — `pc0`, `pc1` и т. д.
Следующие этапы разрешают ID только в непосредственном родителе. Отсутствующие
обученные координаты вызывают ошибку проверки fit.

<a id="rust-construction-and-borrowing"></a>

## Создание и заимствование в Rust

```rust
use fiml::{FeatureExtractorSpec, FeatureId, FittedStage, PipelineSpec, TransformerDefinition};

fn build(raw: FeatureExtractorSpec) -> fiml::Result<fiml::Pipeline> {
    let mut spec = PipelineSpec::new(raw);
    let root = spec.root();
    let lag = spec.add(root, FittedStage::Scalar {
        transformations: vec![TransformerDefinition::lagged(
            FeatureId::new("price"), FeatureId::new("previous_price"), 1,
        )],
    })?;
    spec.output("model", lag)?;
    spec.output("decision", root)?;
    spec.build()
}
```

`pipeline.output(name)` возвращает необязательный заимствованный `PipelineOutput`.
`values()`, `feature_ids()`, `observations()` заимствуют текущий буфер узла.
Сохраняйте `output.id()` между обновлениями и разрешайте через
`pipeline.output_by_id(id)`. ID чужого конвейера отклоняются. Заимствование должно
закончиться до изменения. `reset()` очищает историю, сохраняя параметры и ID выходов.
`raw_values()` включает резервные ячейки для диагностики; выходы корня исключают их.

Среда владеет одним заранее выделенным буфером на узел преобразования и существующим
хранилищем экстрактора. Потомки читают буферы родителей без изменения. Общий узел
выполняется один раз на принятое событие. Вычисление графа и заимствованное чтение
Rust не выделяют память; хранилище стакана рассматривается отдельно.

<a id="training-and-lifecycle"></a>

## Обучение и жизненный цикл

Одна общая `fit_mask` выбирает строки обучения всех оценивателей. Общий оцениватель
обучается один раз за fit. Разные узлы обучаются независимо, даже если созданы из
одного объекта. Исключённые строки всё равно воспроизводятся для лагов и окон.
По необходимости обучение повторяет воспроизведение с пустым состоянием без общего
кэша матриц. Общий узел выполняется один раз на событие внутри каждого прохода,
а не обязательно один раз за всё обучение.

Запускаемый [пример обучения](../../crates/fiml-python/examples/multiple_outputs.py)
обучает общее заполнение медианой над снимками SMA/лага, затем независимые ветви
StandardScaler/PCA и MinMaxScaler/PCA вместе со скалярным выходом решения.
Он использует одну маску, проверяет строки по независимым эталонам NumPy/sklearn
и экспортирует числовой артефакт для работы без sklearn. Общая
[обученная фикстура](../../tests/fixtures/sklearn_multiple_outputs.json) проверяет
выходы Python и отдельного Rust с `rtol=1e-10`, `atol=1e-12`.

Неудачный fit сохраняет прежний артефакт и рабочее состояние. Успешный fit и
загрузка артефакта начинают с пустого состояния. `transform` продвигает рабочий
экземпляр; перед независимым потоком вызывайте `reset()`. Контекст, часы источников,
отклонённые события и синхронизация стакана сохраняют существующую семантику.

<a id="artifacts-and-migration"></a>

## Артефакты и миграция

JSON конвейера `4.0` требует упорядоченные массивы `nodes`, `outputs`. Узел ноль —
экстрактор; преобразование ссылается на более ранний индекс родителя. Вложенная
спецификация экстрактора остаётся `2.0`. Числовые данные этапов прежние.
[Схема](../pipeline-spec.schema.json) проверяет форму записей; Rust также проверяет
ссылки, размерности, раскладки и числовые параметры. Порядок создания узлов и
регистрации выходов сохраняется при сериализации и загрузке.

Экспортируются только конфигурация и обученные числовые параметры. ID владельцев
построителя/экземпляра, текущие значения, часы, история, обучающие строки и объекты
оценивателей не сериализуются. Артефакты `3.0` нужно пересоздать новым построителем
и экспортировать; совместимого загрузчика и автоматической миграции нет.
