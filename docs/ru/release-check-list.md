<a id="local-validation"></a>

## Локальные проверки

Подготовительные проверки 2026-10-24 использовали Rust 1.89.0 и CPython 3.13.5.
Это результаты рабочего дерева, а не подтверждение финального коммита.
Локальная упаковка может использовать `--allow-dirty`; workflow выпуска обязан
упаковывать чистый коммит. Результаты и числа тестов 0.2.0 не переносятся.

- [x] `cargo fmt --all -- --check`
- [x] `cargo +1.89.0 test --all-features`: 352 теста и 2 doctest.
- [x] `cargo +1.89.0 clippy --workspace --all-targets --all-features -- -D warnings`
- [x] `RUSTDOCFLAGS="-D warnings -D missing_docs" cargo +1.89.0 doc -p fiml --all-features --no-deps`
- [x] `RUSTUP_TOOLCHAIN=1.89.0 just test-python`: 932 теста на CPython 3.13.5.
- [x] `RUSTUP_TOOLCHAIN=1.89.0 just test-notebook`: исполнение и экспорт HTML.
- [x] Упаковать и проверить крейт Rust; собрать release-колесо и sdist.
- [x] Проверить версии, метаданные, README/лицензии и необходимые исходники.
- [x] Установить колесо и sdist в отдельные чистые среды CPython 3.12;
  запустить быстрые старты, примеры именованных выходов и миграции.
- [x] Собрать и запустить пример Rust из README с распакованным крейтом и
  экспортом Python; сравнить именованный выход (`1.224745`).

Локальный крейт содержал 114 файлов. Maturin 1.15.0 собрал колесо и sdist;
workflow сохраняет Maturin 1.14.1. Чистые установки CPython 3.12.15 прошли быстрые
старты, примеры миграции и README-воспроизведение Python → Rust; колесо также
прошло все 932 теста Python. Локальное Linux-колесо рассчитано на manylinux 2.34;
только workflow подтверждает требуемые сборки manylinux 2.17.

<a id="final-validation-record"></a>

## Запись финальных проверок

[PR выпуска #204](https://github.com/pbezglasny/fiml/pull/204#issue-0) содержит
SHA кандидата, ссылки на CI и Release, перечень артефактов, контрольные суммы,
поддерживаемые версии и результаты чистых установок. Результаты именно этого SHA являются
подтверждением; пункты ниже — процедура, а не утверждение об успехе. Хранение
результатов в PR не меняет проверенный коммит ради записи его собственного SHA.
Каждый последующий коммит требует новой записи проверок.

- [x] Отправить кандидата и открыть PR подготовки со ссылкой на #202.
- [ ] Запустить `ci.yml` вручную на ветке кандидата; проверить совпадение
  `head_sha` с нужным коммитом и успех всех проверок. Обычный CI PR тоже
  обязателен; его merge checkout не подтверждает точный head.
- [ ] Запустить `release.yml` на той же ветке/коммите. Проверить, что публикация
  не выполнялась, а упаковка и тесты API Linux-колеса прошли.
- [ ] Скачать и проверить ровно семь артефактов: крейт, sdist и колёса
  Linux x86-64/AArch64, macOS x86-64/AArch64, Windows x86-64.
- [ ] Проверить версии 0.3.0, ABI-теги CPython 3.12, метаданные, README/лицензии
  и необходимые исходники скачанных пакетов.
- [ ] Установить скачанные колесо Linux x86-64 и sdist в отдельные чистые среды;
  запустить быстрые старты и воспроизведение именованных выходов Python → Rust
  со скачанным крейтом. Записать результаты в запись финальных проверок.

<a id="tagging-and-publishing-separate-step"></a>

## Тег и публикация (отдельный шаг)

Ручной запуск workflow собирает без публикации. Отправка `v0.3.0` запускает
`.github/workflows/release.yml`, публикующий crates.io и PyPI, затем GitHub Release.
Не загружайте пакеты вручную заранее. Подготовка #202 завершается до слияния,
создания тега и публикации.

- [ ] Подтвердить дату публикации и финальные успешные проверки точного коммита.
- [ ] Проверить готовность `CARGO_REGISTRY_TOKEN` и PyPI Trusted Publishing.
- [ ] Создать `v0.3.0` на проверенном коммите и отправить тег.
- [ ] Проверить `fiml` 0.3.0 в обоих реестрах, семь артефактов и заметки GitHub.
- [ ] Проверить чистые установки `cargo add fiml@0.3.0` и `pip install fiml==0.3.0`,
  документацию и метаданные реестров.
