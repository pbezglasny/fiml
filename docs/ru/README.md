# Fiml

<a id="description"></a>

## Описание

Fiml — библиотека подготовки признаков для торговли и машинного обучения.
Формируйте признаки из исторических рыночных данных в Python, а затем используйте
те же вычисления для событий в реальном времени в Rust. Векторы признаков подходят
для моделей LightGBM, XGBoost, CatBoost, scikit-learn и других ML-библиотек.

* **Потоковые вычисления** — обновляйте индикаторы и векторы признаков по мере
  поступления цен, объёмов, сделок и событий стакана без пересчёта всей истории.
* **Единое вычислительное ядро** — Python использует движок Rust, поэтому при
  одинаковой конфигурации и последовательности событий исторические и потоковые
  расчёты согласованы.
* **Минимум выделений памяти** — повторно используйте хранилище результатов и
  заимствуйте значения в Rust без копирования вектора. При создании выделяется
  память для внутреннего состояния; остальные затраты зависят от операции и API.
* **Переносимые конвейеры** — экспортируйте определения признаков и обученные
  параметры преобразований из Python в JSON и восстанавливайте конвейер в Rust.
* **Предобработка для модели** — объединяйте индикаторы с масштабированием,
  лагами, заполнением пропусков и PCA, чтобы получить входной вектор модели.

Fiml активно развивается. До версии 1.0 минорные выпуски могут содержать
несовместимые изменения; инструкции по миграции см. в [журнале изменений](CHANGELOG.md).

<a id="overview"></a>

## Обзор

Fiml превращает поток рыночных событий в упорядоченный вектор входов модели:

```text
Events → Feature extractor → Raw features → Transformations → Model inputs
```

* **События** содержат обновления цен, объёмов, сделок или стакана с временными
  метками. События времени поддерживают глобальные календарные признаки. Поток
  может поступать из исторических данных или из источника реального времени.
* **Определения признаков** описывают каждый выход: расчёт, символ, источник,
  параметры (например, размер окна) и идентификатор. `FeatureExtractorSpec`
  объединяет определения в конфигурацию для повторного использования.
* **Экстрактор признаков** хранит историю индикаторов и обновляет исходные
  значения при поступлении соответствующих событий. `FeatureExtractor` предоставляет
  их в векторе признаков с идентификаторами выходов.
* **Преобразования** подготавливают признаки для модели: выбирают и масштабируют
  значения, добавляют лаги или применяют поддерживаемые параметры, обученные в
  Python, например значения заполнения пропусков и компоненты PCA.
* **Конвейер** объединяет экстрактор и преобразования. `PipelineSpec` описывает
  конфигурацию; `Pipeline` в Rust и `ModelInputPipeline` в Python исполняют общий
  граф и предоставляют именованные выходные векторы. Интеграция с моделью
  использует эти выходы для прогнозирования.

Спецификации экстрактора и конвейера сериализуются в JSON и загружаются в обоих
языках. Обычный процесс: определить признаки и обучить поддерживаемые преобразования
на исторических данных в Python, экспортировать конвейер и восстановить его в Rust
для работы в реальном времени. JSON хранит конфигурацию и обученные параметры;
историю индикаторов и состояние стакана нужно восстановить, подав события в новый
экземпляр среды исполнения.

<a id="supported-features"></a>

## Поддерживаемые возможности

<a id="indicators-and-market-features"></a>

### Индикаторы и рыночные признаки

Эти признаки доступны в экстракторах Rust и Python. Размеры окон, лаги в отсчётах,
символы и применимые источники входных данных настраиваются.

| Категория | Поддерживаемые признаки |
| --- | --- |
| Исходные поля и контекст | Последние значения цены или объёма; внешние значения, сохраняемые до замены или очистки. |
| Доходности | Простая и логарифмическая доходность с лагами в отсчётах. |
| Скользящие средние | Простая скользящая средняя (SMA) во временных окнах. SMA по отсчётам и EMA относятся к преобразованиям конвейера. |
| Волатильность | Скользящее стандартное отклонение генеральной совокупности простых доходностей в окнах по отсчётам или времени. |
| Торговая активность | Число сделок, суммарный объём и средневзвешенная по объёму цена (VWAP) во временных окнах. |
| Поток объёма | Накопленная дельта объёма (CVD) в окнах по отсчётам, балансовый объём (OBV) во временных окнах и накопленный ценовой тренд объёма (VPT). |
| Календарь | День недели UTC и время с первого события дня; фиксированное смещение UTC для границ дня настраивается. |
| Котировки стакана | Лучшие цены и объёмы покупки/продажи, средняя цена, спред, спред в базисных пунктах, взвешенная средняя цена и микропрайс. |
| Глубина стакана | Объём на цене, цена или объём на заданной глубине, накопленная глубина до цены, диапазон цен и суммарный объём для достижения целевого объёма, объём между ценами и дисбаланс bid/ask. |
| Поток стакана | Добавленный и удалённый объём bid/ask по всем уровням каждой непосредственно применённой дельты. Снимки и повторное воспроизведение не формируют поток. |

Временные индикаторы используют настраиваемые интервалы агрегации. CVD требует
сторону агрессора сделки; признаки стакана — настроенный стакан со снимками и дельтами.

Ключи потока в Rust: `OrderBookBidAddedVolume`, `OrderBookBidRemovedVolume`,
`OrderBookAskAddedVolume`, `OrderBookAskRemovedVolume`, каждый с `symbol`.
Добавляйте их через `FeatureExtractor::builder(...).add_feature(...)` или
`FeatureExtractorSpec` с настроенным стаканом. Передавайте их ID обычным скалярным
SMA/EMA; [пример потока в Python](crates/fiml-python/README.md#order-book-addremove-flow)
показывает тот же артефакт и правила обработки снимков и воспроизведения.

<a id="transformations"></a>

### Преобразования

Конвейеры поддерживают скалярные преобразования и последовательности обученных
этапов предобработки. Поддерживаемые оцениватели Python экспортируют обученные
параметры для исполнения в Rust.

| Операция | Поддерживаемые преобразования |
| --- | --- |
| Скалярные операции | Копирование, переименование и перестановка признаков; масштабирование по заданным среднему и масштабу; сглаживание наблюдений SMA/EMA по отсчётам; скользящие std/min/max/range в окнах по отсчётам или времени; лаги по числу принятых событий. |
| Обучаемое масштабирование | `StandardScaler`, `RobustScaler`, `MinMaxScaler`, `MaxAbsScaler`. |
| Преобразования распределения | `PowerTransformer` с Box-Cox или Yeo-Johnson; `QuantileTransformer` с равномерным или нормальным выходным распределением. |
| Пропуски | `SimpleImputer` для NaN со средним, медианой, наиболее частым значением или константой; необязательные индикаторы пропусков. |
| Отбор признаков | Явный выбор столбцов и обученный отбор `VarianceThreshold`. |
| Снижение размерности | PCA с необязательным отбеливанием. |

Для обучения в Python нужен необязательный набор зависимостей `fiml[sklearn]`.
Поддерживаемые параметры и ограничения описаны в
[документации предобработки Python](crates/fiml-python/README.md#fitting-sklearn-stages).

Python также предоставляет [`future_value`](crates/fiml-python/README.md#time-horizon-training-targets)
для обучающих меток по прошедшему времени, отдельно от воспроизведения признаков.
Формируйте метки отдельно для каждого инструмента и хронологической части выборки.

<a id="installation"></a>

## Установка

Примеры рассчитаны на **0.2.0**. Пока эта версия не опубликована в crates.io и PyPI,
устанавливайте из исходников по инструкциям ниже.

<a id="rust"></a>

### Rust

Нужны Rust **1.89 или новее** и системный компоновщик вашей платформы.
Из каталога приложения добавьте Fiml из crates.io:

```bash
cargo add fiml@0.2.0 --features serde
cargo add serde_json --features float_roundtrip
```

Возможность `serde` включает JSON-сериализацию спецификаций признаков и конвейеров.
`serde_json` читает и записывает их; `float_roundtrip` сохраняет обученные параметры
с плавающей точкой при загрузке. Для приложения только на Rust без обмена JSON
можно не указывать `--features serde` и зависимость `serde_json`.

Установка разрабатываемой версии из Git:

```bash
cargo add fiml --git https://github.com/pbezglasny/fiml --features serde
```

<a id="python"></a>

### Python

Нужен **CPython 3.12 или новее**. Создайте виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируйте его командой `source .venv/bin/activate` в Linux/macOS или
`.\.venv\Scripts\Activate.ps1` в Windows PowerShell. Установите пакет из PyPI:

```bash
python -m pip install "fiml[pandas]>=0.2.0,<0.3"
```

Совместимый wheel не требует инструментов Rust. При сборке pip из исходников
нужны описанные выше Rust и компоновщик. NumPy устанавливается вместе с пакетом.
Необязательный набор `pandas` включает ввод и вывод DataFrame; при использовании
только NumPy API опустите `[pandas]`.

Для обучения поддерживаемых преобразований scikit-learn:

```bash
python -m pip install "fiml[pandas,sklearn]>=0.2.0,<0.3"
```

Набор `sklearn` сейчас требует scikit-learn `>=1.9,<1.10`.
Установка из исходников, настройка среды разработки и устранение неполадок описаны
в [руководстве по установке Python](crates/fiml-python/README.md#install-from-source).

<a id="simple-example"></a>

## Простой пример

Вычислим среднюю по трём отсчётам, обучим масштабирование в Python и экспортируем
конвейер для Rust. Пример требует набора `sklearn` из раздела установки.

<a id="python-fit-and-export"></a>

### Python: обучение и экспорт

Сохраните код в `prepare_pipeline.py` и выполните `python prepare_pipeline.py`.
Он запишет `pipeline.json` в текущий каталог.

```python
from pathlib import Path

import fiml
import numpy as np
from sklearn.preprocessing import StandardScaler

raw = fiml.FeatureExtractorSpec().field("BTCUSDT", source="price", id="price")
spec = fiml.PipelineSpec(raw)
smoothed = spec.add(spec.root(), fiml.ScalarStage().sma("price", window=3, output="sma3"))
scaled = spec.add(smoothed, StandardScaler())
spec.output("model", scaled)
pipeline = spec.build()

prices = np.array([100.0, 102.0, 104.0, 106.0, 108.0])
model_inputs = pipeline.fit_transform(
    kind=np.full(len(prices), fiml.KIND_PRICE, dtype=np.uint8),
    symbol=np.full(len(prices), pipeline.symbol("BTCUSDT"), dtype=np.int64),
    timestamp=np.arange(len(prices), dtype=np.int64) * 1_000,
    price=prices,
    fit_mask=np.arange(len(prices)) >= 2,  # Exclude the two warm-up rows.
)["model"]

assert np.isnan(model_inputs[:2]).all()
np.testing.assert_allclose(model_inputs[-1, 0], np.sqrt(1.5))
Path("pipeline.json").write_text(pipeline.to_json(), encoding="utf-8")
print(f"Final model input: {model_inputs[-1, 0]:.6f}")
```

Масштабирование обучается на готовых значениях SMA `[102, 104, 106]`. Результат
содержит строку на каждое событие, включая начальные строки `NaN`. В реальном
процессе обучайте предобработку только на обучающей выборке, а для валидации и
прогнозирования используйте конвейер с зафиксированными параметрами.

<a id="rust-load-and-replay"></a>

### Rust: загрузка и воспроизведение

Сохраните код в `src/main.rs` приложения Cargo, настроенного в разделе установки.
Поместите `pipeline.json` в корень приложения и выполните там `cargo run`.

```rust
use fiml::{Event, PipelineSpec, Symbol};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let json = std::fs::read_to_string("pipeline.json")?;
    let spec: PipelineSpec = serde_json::from_str(&json)?;
    let mut pipeline = spec.build()?;
    let output = pipeline.output("model").unwrap().id();
    let btc = Symbol::new("BTCUSDT")?;

    // Rebuild indicator history; fitted scaler parameters came from JSON.
    for (index, price) in [100.0, 102.0, 104.0, 106.0, 108.0].into_iter().enumerate() {
        pipeline.handle_event(Event::price(btc, price, index as i64 * 1_000))?;
        if index < 2 {
            assert!(pipeline.output_by_id(output).unwrap().values()[0].is_nan());
        }
    }

    let model_input: &[f64] = pipeline.output_by_id(output).unwrap().values();
    assert!((model_input[0] - 1.5_f64.sqrt()).abs() < 1e-12);
    println!("Final model input: {:.6}", model_input[0]);
    Ok(())
}
```

Обе программы выводят `Final model input: 1.224745`. Продолжайте подавать новые
ценовые события в конвейер Rust и передавайте модели заимствованный выходной срез.

<a id="behavior-and-limits"></a>

## Поведение и ограничения

* **Прогрев и пропуски:** при `WarmupPolicy::FullWindow` оконные признаки выдают
  `NaN`, пока не накопится достаточно отсчётов или времени событий. Это значение
  по умолчанию в построителях Python; `FirstValue` разрешает неполное окно.
  Доходностям всегда нужен точный лаг по отсчётам. Для простой доходности прошлое
  значение должно быть ненулевым, для логарифмической оба значения — положительными.
  Отсутствующие уровни стакана и пустые окна VWAP могут давать `NaN` и после прогрева.
* **Время событий:** метки — миллисекунды Unix epoch, неубывающие для каждого
  символа по всем видам событий. Символы могут чередоваться; лаги конвейера считают
  принятые события в порядке поступления. Временные окна экстрактора продвигаются
  событиями своего символа. Глобальные события `Time` не продвигают окна других
  символов. Отдельные временные индикаторы имеют `observe(timestamp)` для
  продвижения времени без данных. Временные SMA, OBV, число и объём сделок, VWAP
  поддерживают полный знаковый диапазон `i64` в отдельных индикаторах, экстракторах
  и конвейерах. Начала интервалов округляются вниз до кратных агрегации, включая
  отрицательное время; интервал истекает при `bucket_start + window <= timestamp`,
  даже если начало или срок истечения выходят за `i64`. Длительности — положительные
  целые миллисекунды до `i64::MAX`; окна кратны агрегации и ограничены ёмкостью истории.
* **Преобразования по прошедшему времени:** `TransformerDefinition::lagged_timed`,
  `delta_timed`, `simple_return_timed`, `log_return_timed` принимают положительную
  `Duration` в целых миллисекундах. Например,
  `TransformerDefinition::delta_timed(FeatureId::new("microprice"),
  FeatureId::new("change_500ms"), Duration::from_millis(500))` сравнивает текущее
  наблюдение с последним конечным значением не позднее времени источника минус
  500 мс. Они работают и после скалярных/обученных этапов. Окна совместно используют
  историю для одного входа, агрегации и этапа. Агрегация по умолчанию 1 мс точна.
  Для более грубой истории используйте соответствующий конструктор
  `_with_aggregation(input, output, lag_window, aggregation)`. Лаг 24 часа с
  агрегацией 1 секунда резервирует около 1,38 МБ. Интервал хранит последнее конечное
  наблюдение и его фактическую метку; промежуточные наблюдения отбрасываются.
  Поиск никогда не выбирает наблюдение позже границы. Лаг должен быть положительным
  и кратным агрегации; `max_lag / aggregation + 2` не больше 1 000 000 ячеек
  (около 16 МБ на общую историю). Более крупные конфигурации отклоняются до выделения
  памяти. Интерполяции нет; выход остаётся NaN до появления подходящего наблюдения.
* **Преобразования траектории:** `rolling_slope`, `rolling_path_length`,
  `rolling_positive_movement`, `rolling_negative_movement`,
  `rolling_direction_change_count`, `rolling_max_drawdown` описывают недавнюю
  траекторию скаляра предыдущего этапа. Окна считают конечные наблюдения; совместимые
  выходы используют общие логарифмические обновления истории без выделений памяти.
  Наклон требует двух наблюдений, нулевые изменения не считаются разворотами,
  просадка выражена в абсолютных единицах входа. См.
  [определения и примеры](pipeline.md#rolling-trajectory-shape).
* **Серии и давность состояния:** `positive_streak`, `negative_streak`,
  `observations_since_positive`/`negative`/`nonzero` и
  `time_since_positive`/`negative`/`nonzero` описывают устойчивость знака входа.
  Применяйте их после дельт/доходностей или к исходным знаковым признакам.
  Epsilon задаёт включительный нейтральный интервал; давность измеряется в
  миллисекундах. Память постоянна, обновления не выделяют память. См.
  [семантику состояния](pipeline.md#streak-and-state-age-transformations).
* **Проверка входа:** экстракторы и конвейеры отклоняют NaN, бесконечности в числовых
  полях событий и нарушенный порядок времени. Отдельные индикаторы полагаются на
  конечные входы и упорядоченное время от вызывающего кода. Обрабатывайте ошибки
  стакана и передавайте свежий снимок при необходимости повторной синхронизации.
* **Состояние:** пакет обновляет ту же историю, что и отдельная обработка событий.
  Для независимого потока создайте новый экземпляр; `ModelInputPipeline` в Python
  также предоставляет `reset()`. JSON загружает пустую историю событий, сохраняя
  обученные параметры преобразований.
* **Расположение и точность выходов:** определяйте столбцы по ID признаков, а не по
  порядку вызовов построителя. Rust использует `f64`; Python по умолчанию возвращает
  `float64` и может приводить выходы к `float32`. Именованные выходы содержат только
  активные координаты. Диагностика экстрактора может включать зарезервированные
  ячейки, остающиеся `NaN`. См. [API графа и выходов](multiple_output.md).
* **Выделения памяти:** обновления встроенных индикаторов и преобразований используют
  заранее выделенную память. Создание, работа с JSON, выходные массивы и DataFrame
  Python, хранилище стакана могут выделять память. Заимствование срезов Rust
  позволяет избежать копирования значений.

Текущие ограничения конфигурации:

| Ограничение | Область действия |
| --- | --- |
| 512 имён символов | На процесс, включая глобальный символ. Регистр ASCII не учитывается; слоты не освобождаются. |
| 16 совместимых выходов | На скомпилированную группу индикаторов, например окна с общей конфигурацией. |
| 1–10 000 событий | Глубина каждого лага конвейера. Не относится к лагам индикаторов доходности. |
| Целые миллисекунды | Интервалы агрегации и временные окна; окно — положительное кратное агрегации. |

<a id="version-and-platform-support"></a>

### Поддерживаемые версии и платформы

Минимальные версии — Rust 1.89 и CPython 3.12. Заявлены Python 3.12, 3.13, 3.14.
Процесс выпуска собирает wheel для Linux x86-64/AArch64, macOS x86-64/AArch64 и
Windows x86-64. Установка из исходников требует Rust и системного компоновщика.
Проверки артефактов отслеживаются в [списке проверок выпуска](release-check-list.md).

<a id="development"></a>

## Разработка

Задачи репозитория используют [just](https://github.com/casey/just).
Для Python и блокнотов также нужен [uv](https://docs.astral.sh/uv/).

```bash
just --list       # Show available tasks
just build        # Build the Rust library and Python wheel (also the default)
just test         # Run Rust tests, Python tests, and the maintained notebook
just test-rust    # Run only Rust tests
just test-python  # Run only Python tests
just marimo       # Open the notebook editor
```

Тест пропускной способности скомпилированного пути от событий к вектору:

```bash
cargo bench -p fiml --bench compiled_dispatch
# Run the workload assertions once without collecting timings:
cargo bench -p fiml --bench compiled_dispatch -- --test
```

Он сравнивает `FeatureExtractor::handle_event` и `Pipeline::handle_event` для
1, 4 и 16 подписанных символов, соответственно с 1, 3 и 4 окнами (8–512 отсчётов
или временных интервалов). ID замеров содержат число исходных/модельных выходов.
Детерминированный поток смешивает события цены, объёма, сделок и времени, а также
посторонний символ, который всё же продвигает глобальный признак прошедшего времени.
Экстракторы считают временные SMA и число сделок; конвейеры добавляют тождественное
преобразование, стандартное масштабирование, SMA/EMA по отсчётам и общие лаги событий.

Создание, полный прогрев, проверки выходов и подготовка пакетов не входят в замер.
Каждая итерация обрабатывает подготовленный пакет в сохраняющем состояние экземпляре,
читает выходы через `black_box` и продолжает метки времени предыдущего пакета.
Учитываются все события, включая посторонние символы и тики часов. Гарантии по
памяти проверяет `cargo test -p fiml --test pipeline_allocations`; порога времени
для CI нет.
