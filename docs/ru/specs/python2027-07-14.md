# Python API DataFrame сделок

Статус: согласовано\
Дата согласования: 2026-07-14

<a id="goal"></a>

## Цель

Небольшой удобный для блокнотов API принимает загруженный pandas DataFrame сделок
и возвращает состояние вектора сразу после каждой сделки. Файлы и хранение вне `fiml`.

Канонический вход соответствует `notebooks/trades.csv`:

```text
symbol,ts,price,volume
BTCUSDT,1783950118926,1,3
```

<a id="public-api"></a>

## Публичный API

```python
extractor = fiml.FeatureExtractor(feature_extractor_spec, output_dtype="float32")

features = extractor.compute_features(
    trades,
    symbol="symbol",
    time="ts",
    price="price",
    volume="volume",
)
```

`compute_features` только для сделок. Старые `source` и баровый `close` удалены.
Низкоуровневые `update`, `transform` поддерживают все виды.

Четыре аргумента столбцов необязательны и имеют показанные имена по умолчанию.
Они должны указывать разные существующие столбцы. Свои имена символа/времени
сохраняются в выходе.

<a id="input-contract"></a>

## Контракт входа

- pandas DataFrame с уникальными метками столбцов.
- `symbol` — непустые строки, без приведения через `str`.
- `time` — знаковые `int64` Unix-миллисекунды. Datetime, float, строки запрещены,
  неявной конверсии нет.
- `price`, `volume` — целые/дробные, внутри приводятся к `float64`, конечны и строго положительны.
- Несколько символов поддерживаются.
- Время не убывает по символу в порядке DataFrame; равные метки сохраняют порядок.
- Порядок по символу охватывает повторные `compute_features`, `update`, `transform`
  того же экстрактора.
- Весь вход проверяется до первого события. Неудача сохраняет индикаторы и временную границу.
- Ошибка указывает позицию строки от нуля, метку индекса pandas и столбец, если применимо.

Пустой DataFrame успешен, имеет ожидаемые пустую форму/dtype, не блокирует и не
меняет экстрактор.

<a id="output-contract"></a>

## Контракт выхода

Результат — pandas DataFrame с исходным индексом. Столбцы:

1. Копия символа.
2. Копия времени.
3. Числовые признаки в порядке `feature_names()`.

Строка — полный снимок сразу после сделки. В многосимвольном потоке остальные
символы сохраняют состояние. Ячейки остаются `NaN` до прогрева.

Средние явно задают поле через `source="price"`, `"volume"`, `"trade_price"`,
`"trade_volume"`. Источник определяет маршрут и поле, явно хранится в спецификации.
`compute_features` создаёт сделки: используйте `trade_price`/`trade_volume`;
стандартный источник построителя остаётся `price`.

Метаданные не входят в числовой вектор: `feature_names()`, `n_features()` описывают
только признаки. Их имена уникальны и не конфликтуют с выбранными метаданными.

<a id="output-dtype"></a>

## Тип выхода

Расчёты/состояние всегда `float64`. `output_dtype` управляет только массивами и
столбцами `values`, `transform`, `compute_features`.

Конструктор/сеттер принимают `"float32"`, `"float64"`, `numpy.float32`,
`numpy.float64`. По умолчанию `"float64"`; getter возвращает каноническую строку.

Менять можно до первого успешно обработанного события; после — `ValueError`.
Пустые/неудачные вызовы не блокируют. Пример конструктора:

```python
fiml.FeatureExtractor(feature_extractor_spec, output_dtype="float32")
```

<a id="packaging-and-verification"></a>

## Упаковка и проверка

- Python 3.12+, `abi3-py312`.
- DataFrame через набор `pandas` с `pandas>=2.0`.
- Регрессионные тесты проверки, атомарности, порядка, dtype, метаданных,
  многосимвольных снимков и прогрева.
- `notebooks/test.ipynb` — исполняемый сквозной пример на `notebooks/trades.csv`.
- CI pull request собирает/устанавливает wheel на Python 3.12, запускает тесты
  и блокнот без коммита сгенерированного вывода.
