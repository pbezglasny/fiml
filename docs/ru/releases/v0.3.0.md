# Fiml 0.3.0

Выпуск добавляет общие графы преобразований с именованными выходами моделей,
новые скользящие преобразования и состояния, исправления границ времени.

<a id="highlights"></a>

## Основные изменения

- Обучайте независимые ветви sklearn поверх общих этапов и получайте выходы
  моделей и решений за одно воспроизведение. Rust заимствует буферы без
  выделения памяти; Python возвращает независимые снимки.
- Применяйте дельты/доходности, временные лаги и изменения, скользящую статистику,
  измерения траектории, экспериментальные сигнатуры пути, серии и возраст
  состояний к признакам предыдущего этапа.
- Измеряйте добавленный/удалённый объём bid/ask напрямую применённых дельт стакана.
- Завершены приёмочные проверки доходности по отсчётам и волатильности доходности
  в Rust и Python. Временные индикаторы обрабатывают крайние метки signed-int64.
- Добавлены русская документация и команды разработки через `just`.

<a id="migration-from-020"></a>

## Миграция с 0.2.0

<a id="build-a-graph-and-name-every-output"></a>

### Постройте граф и назовите каждый выход

Замените старый линейный конструктор/добавление этапов на
`root()` / `add(parent, stage)` / `output(name, node)` / `build()`.
Даже единственный выход нужно зарегистрировать. Неявного последнего выхода
и метода `values()` на уровне конвейера больше нет.

```python
import fiml
import numpy as np

raw = fiml.FeatureExtractorSpec().field("BTCUSDT", id="price")
spec = fiml.PipelineSpec(raw)
node = spec.add(spec.root(), fiml.ScalarStage().identity("price"))
spec.output("model", node)
pipeline = spec.build()
result = pipeline.transform(
    kind=np.array([fiml.KIND_PRICE], dtype=np.uint8),
    symbol=np.array([pipeline.symbol("BTCUSDT")], dtype=np.int64),
    timestamp=np.array([0], dtype=np.int64),
    price=np.array([100.0]),
)
assert list(result) == ["model"]
assert result["model"].shape == (1, 1)
assert pipeline.output_names() == ["model"]
assert pipeline.output("model").values()[0] == 100.0
```

`transform`, `fit_transform`, `transform_order_book` возвращают словари матриц
в порядке регистрации, даже при одном выходе. `compute_features` возвращает
словарь DataFrame. Выберите имя перед передачей данных модели. Просматривайте
выход через `output(name)`. Дополнительные имена на существующих или новых
узлах позволяют разделять вычисления; этап ищет ID у непосредственного
родителя. Обучите рецепты оценщиков перед расчётом/экспортом; одна `fit_mask`
действует на все ветви.

В Rust создайте `PipelineSpec::new(raw)`, добавьте узлы `FittedStage`,
зарегистрируйте выходы и соберите конвейер. `pipeline.output("model")` возвращает
необязательное заимствованное представление с `values()`, `feature_ids()`,
`observations()`. Сохраните `id()` и используйте `output_by_id(id)` между
обновлениями; завершайте заимствования перед изменением состояния. См.
[примеры Rust](https://github.com/pbezglasny/fiml/blob/v0.3.0/docs/ru/multiple_output.md#rust-construction-and-borrowing) и
[быстрый старт Python → Rust](https://github.com/pbezglasny/fiml/blob/v0.3.0/docs/ru/README.md#simple-example).

<a id="recreate-pipeline-artifacts"></a>

### Пересоздайте артефакты конвейера

| Версия | Значение |
| --- | --- |
| `0.3.0` | Выпуск крейта Rust и пакета Python |
| `4.0` | JSON графа конвейера с упорядоченными `nodes` и `outputs` |
| `2.0` | JSON вложенного экстрактора, не изменён в этом выпуске |

JSON конвейера `3.0` отклоняется. Пересоздайте граф и экспортируйте артефакт
версией 0.3.0; обучите рецепты перед экспортом. **Не меняйте только строку
версии**: нужны структура графа и зарегистрированные выходы. JSON хранит
конфигурацию и обученные численные параметры, а не живые значения, часы,
историю индикаторов/стакана или контекст. После загрузки воспроизведите прогрев
и восстановите контекст. Python `transform` продвигает состояние; сбрасывайте
его перед независимым воспроизведением.

<a id="update-removed-arguments-and-rust-types"></a>

### Обновите удалённые аргументы и типы Rust

- Удалите аргументы Python `bid`, `ask` из `update`, `transform`, `fit`,
  `fit_transform`, даже со значением `None`. Используйте `OrderBookEvent` с
  `update_order_book` / `transform_order_book`; скалярный `KIND_ORDERBOOK` отклоняется.
- Варианты Rust `FeatureKey` только для сделок больше не принимают `source`.
  Варианты со скалярным источником принимают `EventField` напрямую вместо
  `FeatureSource::Field(field)`.
- Создавайте `TransformerDefinition` с полями `input`, `output`, `operation`
  или используйте прежние удобные конструкторы. Разбирайте параметры
  `TransformerOperation` через `definition.operation`.

[Журнал изменений](https://github.com/pbezglasny/fiml/blob/v0.3.0/docs/ru/CHANGELOG.md) перечисляет варианты и
исправления. [Руководство Python](https://github.com/pbezglasny/fiml/blob/v0.3.0/docs/ru/crates/fiml-python/README.md) описывает
актуальные сигнатуры и воспроизведение стакана.

<a id="support-and-release-status"></a>

## Поддержка и состояние выпуска

Нужен Rust **1.89+** или CPython **3.12+**. Колёса: Linux x86-64/AArch64,
macOS x86-64/AArch64, Windows x86-64. NumPy обязателен; дополнения `pandas`
и `sklearn` необязательны. Лицензия Apache-2.0.

Дата публикации пока не назначена. Проверки отражены в
[списке выпуска](https://github.com/pbezglasny/fiml/blob/v0.3.0/docs/ru/release-check-list.md). Ручной запуск workflow собирает
артефакты без публикации; отправка `v0.3.0` публикует через существующий workflow.
