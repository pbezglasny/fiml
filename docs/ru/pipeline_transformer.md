<a id="recommendation"></a>

## Рекомендация

Обучайте поддерживаемые преобразования sklearn в Python, экспортируйте числовое
состояние в `PipelineSpec` и исполняйте его одним движком Rust в пакетном Python
и онлайн. Поддерживаются `SimpleImputer`, `StandardScaler`, `RobustScaler`,
`MinMaxScaler`, `MaxAbsScaler`, `PowerTransformer`, `QuantileTransformer`,
`VarianceThreshold`, `PCA`, включая отбеливание. Привязывайте скалярные и векторные
этапы к явным родительским узлам.

«Сохранить параметры» означает обученное состояние для применения. Одних аргументов
конструктора вроде `n_components=2` недостаточно для PCA: нужны оси и среднее;
ширина выхода тоже может определяться обучением. См.
[атрибуты PCA](https://scikit-learn.org/stable/modules/generated/sklearn.decomposition.PCA.html).

Это экспорт конкретных типов sklearn. Произвольный объект с `fit`/`transform`
не исполняется в Rust лишь потому, что параметры сериализуются: Rust должен
реализовать его операцию. Неподдерживаемые типы отклоняются при добавлении, до данных.

<a id="python-graph-interface"></a>

## Интерфейс графа Python

Создавайте узлы через `PipelineSpec.add(parent, stage)`, регистрируйте выходы и
вызывайте `build()`. Общий родитель разделяет обучение и состояние. Каждое
добавление сохраняет снимок переданной конфигурации.

```python
import fiml
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

raw = (fiml.FeatureExtractorSpec()
       .field("BTCUSDT", source="trade_price", id="price")
       .field("BTCUSDT", source="trade_volume", id="volume"))
spec = fiml.PipelineSpec(raw)
scaled = spec.add(spec.root(), StandardScaler())
projected = spec.add(scaled, PCA(n_components=2))
spec.output("model", projected)
spec.output("decision", spec.root())
pipeline = spec.build()
# Register symbols, then supply the usual event columns.
# pipeline.fit(**training_events, fit_mask=training_rows)
# matrices = pipeline.transform(**following_events)
# latest = pipeline.output("model").values()
```

[API графа](multiple_output.md) задаёт владение, дескрипторы, словари пакетных
результатов, транзакционный fit, сброс и сериализацию. Топология готового конвейера
фиксирована; метода `add_transformation` нет. Артефакты только для применения,
не восстанавливают описания оценивателей. Обучение принимает столбцовые события
и расписания контекста; адаптеров обучения по стакану/DataFrame нет.
Применение поддерживает оба пути воспроизведения.

## Строки обучения, прогрев и воспроизведение

До отбора строк воспроизведите каждое событие в новом базовом конвейере. Пропуск
меняет средние и лаги принятых событий. Используйте проверку Rust, порядок времени
по символу и порядок поступления; не сортируйте/перемешивайте поток ради sklearn.

Создайте временную плотную матрицу `float64` активных выходов родителя оценивателя.
Необязательная `fit_mask` — одномерный булев массив по числу событий. Она выбирает
снимки для всех этапов, не подавляя события. Без маски обучают все снимки.
Выборка непуста, выбранные значения конечны, кроме входов SimpleImputer,
PowerTransformer, QuantileTransformer: они допускают NaN, но не бесконечность.
Сообщайте первую ошибочную строку события и ID. Пользователь может исключить прогрев.
Не заменяйте NaN молча и не удаляйте разные строки независимо вне этого этапа.

Для этапа sklearn: клонировать, обучить по маске, экспортировать состояние.
Для скалярного: проверить и добавить определения. Все исходные события повторяются
с пустого состояния через завершённый префикс Rust для следующей матрицы.
Общие оцениватели обучаются раз за операцию, общего кэша графа нет. Не применяйте
маску до воспроизведения: исключённые строки тоже продвигают последующие лаги.
Проверяйте конечность выбранных входов и конечных выходов. Скалярный отбор может
убрать ненужные столбцы прогрева до следующего оценивателя. Повторное извлечение
для префиксов делает стоимость обучения пропорциональной числу этапов; онлайн
событие обрабатывается один раз. `copy=False` не поддерживается.

Обучение всегда `float64`, даже при выходном `float32`; приводите только конечные
массивы. Последующую модель обучайте на Rust-результате `transform` FIML с теми же
dtype и активными столбцами, что будут при применении.

`transform` сохраняет строки и выравнивание меток. Скалярное масштабирование
сохраняет распространение NaN. Любой неконечный вход PCA делает весь его выход NaN;
проверка явная, включая нулевые веса компонент. Это прогрев FIML, а не утверждение,
что PCA sklearn принимает NaN. Исключайте строки из обучения последующей модели
и не прогнозируйте до готовности нужных признаков.

Fit использует только хронологическую обучающую часть. Валидация/тест могут
продолжить поток после воспроизведения обучения через обученный конвейер.
Для отдельного потока — `reset()` и нужная предыстория. JSON восстанавливает
параметры, но не прогрев индикаторов, синхронизацию стакана или лаги.

<a id="fitted-state-and-numerical-operations"></a>

## Обученное состояние и численные операции

Используйте небольшую явную диспетчеризацию точных классов `SimpleImputer`,
`StandardScaler`, `RobustScaler`, `MinMaxScaler`, `MaxAbsScaler`, `PowerTransformer`,
`QuantileTransformer`, `VarianceThreshold`, `PCA`. Отклоняйте подклассы с возможной
переопределённой логикой, callbacks, разреженные выходы и неподдерживаемые версии/
параметры с понятной ошибкой. Реестр плагинов и зависимость Rust от sklearn не нужны.

<a id="simpleimputer"></a>

### SimpleImputer

Поддерживаются плотный числовой вход, `missing_values=np.nan`, `copy=True`, четыре
встроенные стратегии, `keep_empty_features`, `add_indicator`. Экспортируются лишь
сохранённые индексы входов, конечные значения замены, обученные индексы индикаторов
и явные ID выходов. Rust заменяет только NaN; бесконечности проходят неизменными,
индикаторы показывают пропуски до замены. Заполнение прогрева — явный выбор модели,
не готовность признака; `fit_mask` позволяет исключить такие строки.

<a id="standardscaler"></a>

### StandardScaler

Экспортируйте эффективные `mean[d]`, `scale[d]`: нули при `with_mean=False`,
единицы при `with_std=False`, иначе обученные массивы. Используйте `scale_` sklearn
вместе с обработкой констант; не пересчитывайте его и не считайте наличие `mean_`
признаком включённого центрирования. См.
[StandardScaler](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.StandardScaler.html).

Этап считает `(x[i] - mean[i]) / scale[i]`, по возможности используя существующие
арифметику/проверку скалярного масштабирования. Храните два вектора, не диагональную
матрицу. Время и обученное хранилище — O(d).

<a id="robustscaler"></a>

### RobustScaler

Экспортируйте эффективные `center_[d]`, `scale_[d]` через тот же этап: нули при
`with_centering=False`, единицы при `with_scaling=False`, иначе массивы sklearn
для сохранения `quantile_range`, `unit_variance`, констант и выбросов.
Единичная дисперсия требует `0 < q_min < q_max < 100`; другие диапазоны отклоняйте
при добавлении, поскольку sklearn даёт нулевой/неконечный масштаб. При выключенном
масштабировании диапазон не важен.

<a id="minmaxscaler"></a>

### MinMaxScaler

Экспортируйте `scale_[d]`, `min_[d]` напрямую. Считайте `x[i] * scale[i] + min[i]`
в этом порядке, затем ограничивайте `feature_range` только при `clip=True`.
ID и NaN сохраняются. Масштабы положительны/конечны, смещения и необязательные
строго возрастающие границы конечны. Сохраняется обработка констант и почти констант.
Без ограничения новые данные вне обученного диапазона могут выйти за feature range.

<a id="maxabsscaler"></a>

### MaxAbsScaler

При `clip=False` экспортируйте `scale_[d]` с нулевыми центрами в стандартный этап.
При `clip=True` используйте MinMax с обратными масштабами, нулевыми смещениями
и ограничением `[-1, 1]`. Оба пути сохраняют ID, нули, знаки, NaN за O(d) времени/
памяти. Без ограничения будущий модуль может превысить `1`; обучение неустойчиво к выбросам.

<a id="powertransformer"></a>

### PowerTransformer

Экспортируйте метод, `lambdas_[d]`, эффективные `mean[d]`, `scale[d]` после
преобразования; без стандартизации — нули/единицы. Масштабирование выводите через
публичные функции SciPy и обучение публичного `StandardScaler`, не читая приватный
scaler sklearn. Rust использует устойчивые `log1p`/`expm1` для Yeo-Johnson/Box-Cox
за O(d). NaN сохраняются. Box-Cox запрещает неположительные обучающие значения;
при фиксированном применении только затронутый столбец получает NaN, вместо
отклонения всего события как в sklearn.

<a id="quantiletransformer"></a>

### QuantileTransformer

Экспортируйте `quantiles_[q][d]`, `references_[q]`, выходное распределение,
порог sklearn `1e-7` и конечные границы нормального распределения. Проверьте
конечные прямоугольные таблицы, размерности, неубывание квантилей по столбцам,
строго возрастающие вероятности от `0` до `1` при `q > 1`; повторы квантилей допустимы.
Один раз скомпилируйте построчную таблицу в непрерывные столбцовые таблицы.

Столбец из одних NaN не имеет конечных квантилей: экспортируйте его индекс и
конечный столбец-заглушку. Rust воспроизводит распространение NaN sklearn, чтобы
следующее заполнение могло его обработать. При вырожденном `q = 1` конечные входы
отображаются в `0` (или нижнюю нормальную границу), как в sklearn.

Для значения двоичный поиск обеих сторон повторного квантиля и среднее двух
линейных интерполяций воспроизводят совпадения sklearn за O(log q). Сохраняйте NaN
и насыщайте значения вне обученного диапазона. Uniform заканчивается вероятностью.
Normal применяет рациональное приближение обратной нормальной функции AS 241
Вичуры с точностью плавающей точки в поддерживаемом диапазоне, затем конечные
границы хвостов. Хранилище O(d*q), выделений на событие нет. Нелинейное ранговое
отображение меняет линейные корреляции; выбирайте его осознанно.

Примерные замеры нормального выхода на AMD Ryzen 9 9900X с Criterion
(`cargo bench -p fiml --bench quantile_transform -- --quick`):

| Признаки (`d`) | Квантили (`q`) | Компактный JSON | Медиана на строку |
| ---: | ---: | ---: | ---: |
| 8 | 64 | 21 718 байт | 152 нс |
| 32 | 256 | 274 199 байт | 667 нс |

Размер использует короткие ID и включает весь JSON конвейера. Задержка включает
обновление исходного признака, развёртку базового вектора, двоичный поиск и
нормальное преобразование. Масштабирование соответствует O(d*q) хранения и
O(d*log(q)) поиска; перед планированием мощности повторите на целевом оборудовании.

<a id="variancethreshold"></a>

### VarianceThreshold

`threshold` конечен/неотрицателен, выбранные обучающие входы конечны. После fit
экспортируйте `get_support(indices=True)` как непустой строго возрастающий вектор.
Общий этап отбора хранит только индексы и ID, не дисперсии и не статистику Rust.
Применение копирует O(k) значений в готовый буфер, сохраняя NaN выбранных и
игнорируя удалённые столбцы. Положительный порог зависит от масштаба. Это не отбор
по корреляции и не обучение с учителем.

<a id="pca"></a>

### PCA

Экспортируйте `mean[d]`, `components[k][d]`, `output_scale[k]`. Строки матрицы —
выходные компоненты; столбцы точно следуют предыдущему этапу. `k` — обученное
число компонент, не обязательно исходное `n_components`.

Операция формата:

```text
projected_mean[j] = sum_i(mean[i] * components[j][i])  # computed at build
output[j] = (sum_i(input[i] * components[j][i]) - projected_mean[j])
            / output_scale[j]
```

Обычный PCA использует единицы `output_scale`. Для отбеливания экспортируйте
`max(sqrt(explained_variance_[j]), epsilon_float64)`. Изученная реализация sklearn
сначала проецирует, вычитает спроецированное среднее, затем делит на ограниченный
масштаб. Используйте публичные атрибуты, не приватные методы. См.
[реализацию PCA transform](https://github.com/scikit-learn/scikit-learn/blob/cc50648cc1b759b53a4edbce0f3bb6c237349448/sklearn/decomposition/_base.py).

Эффективный делитель фиксирует ограничение в артефакте вместо вывода версии sklearn
в Rust. Деление остаётся после проекции, не встраивается в матрицу. Проверяйте
конечность средних, компонент, проецированных средних и положительных делителей.
Почти нулевая дисперсия усиливает округление даже с ограничением. Регрессия
недостаточного ранга покрывает `full` и `covariance_eigh`: обычные компоненты —
`rtol=1e-10, atol=1e-12`, почти нулевые — прямая оценка ошибки по величинам входов,
весам и делителю. На почти нулевых компонентах возможны различия со sklearn в целые
единицы; единой малой абсолютной гарантии для произвольного отбеливания нет.
Если это важно, сократите компоненты или выключите отбеливание. Обучайте модель
на матрице FIML: повторная загрузка точно воспроизводит её в том же Rust, включая
вырожденные случаи.

Применение PCA не требует SVD, обучения ковариации или исходных отсчётов.
Вложенный цикл по построчным непрерывным весам стоит O(k*d) на событие и
O(k*d + d + k) памяти. Начните без BLAS, матричной библиотеки, SIMD и слияния этапов;
сначала измерьте характерные размерности.

<a id="json-format-and-validation"></a>

## JSON и проверка

Формат конвейера `4.0` хранит упорядоченные массивы узлов и выходов; экстрактор —
`2.0`. Этапы содержат описанные числовые поля. ID PCA локальны: `pc0`, `pc1` и т. д.
Прочие операции сохраняют правила имён в раскладке узла.

См. [полный пример графа](multiple_output-arc.md#artifact-format-and-compatibility)
и [JSON Schema](../pipeline-spec.schema.json). Rust проверяет индексы родителей,
ссылки, размерности, положительную ширину и конечные параметры до выдачи экземпляра.
Неизвестные поля/версии отклоняются. Чтения совместимости `3.0` нет.

Численное применение реализуют существующие этапы Rust; Python лишь обучает и
экспортирует поддерживаемые оцениватели. Загрузка, граф и расчёты Rust не требуют
sklearn, BLAS и матричных библиотек. Включайте `float_roundtrip` serde_json.
Контракт покрывают общие фикстуры Python/Rust, независимые эталоны sklearn,
транзакционные переобучения, ветвящиеся истории, холодная загрузка и тесты памяти.
