# Журнал изменений

<a id="breaking-change-policy"></a>

## Политика несовместимых изменений

Пакеты Rust и Python используют одну версию выпуска. До `1.0.0` минорные выпуски
(`0.x.0`) могут вносить несовместимые изменения; патчи (`0.x.y`) предназначены для
совместимых исправлений. Изменения публичного API, ID признаков и сериализованной
конфигурации описываются здесь с инструкциями миграции. Версии JSON независимы от
версий пакетов; используйте выпуск, поддерживающий загружаемый формат.

<a id="030--unreleased"></a>

## 0.3.0 — ещё не выпущено

<a id="breaking-changes-and-migration"></a>

### Несовместимые изменения и миграция

- Конвейеры теперь используют расширяемый граф: создайте `PipelineSpec` из
  экстрактора, соедините этапы через `root()` / `add(parent, stage)`, зарегистрируйте
  выходы через `output(name, node)` и вызовите `build()`. Вместо доступа к значениям
  и раскладке конвейера используйте `pipeline.output(name)`; неявного выхода нет.
  Пакетные методы Python возвращают словари в порядке регистрации, даже при одном
  выходе; `compute_features` возвращает словарь DataFrame. Rust предоставляет
  заимствованные `PipelineOutput` и повторно используемые `OutputId`.
  См. [примеры миграции на 0.3.0](releases/v0.3.0.md#migration-from-020).
- JSON конвейера меняется с `3.0` на `4.0`, с упорядоченными `nodes` и `outputs`.
  Пересоздайте и экспортируйте конфигурации и обученные артефакты: одной замены
  строки версии недостаточно. JSON вложенного экстрактора остаётся `2.0`.
  Версии форматов независимы от версии пакета `0.3.0`. JSON хранит конфигурацию
  и обученные параметры, а не живую историю или значения контекста.
- Rust `FeatureKey::{Cvd, ObvTimed, Vpt, TradeCountTimed, TradeVolumeTimed,
  VwapTimed}` больше не принимают `source`: они всегда используют сделки.
  `FeatureKey::{Return, Volatility, SmaTimed, VolatilityTimed}` принимают
  `EventField` напрямую: замените `source: FeatureSource::Field(field)` на
  `source: field`. Недостижимые ошибки `ScalarEventFieldSourceRequired` и
  `TradeEventSourceRequired` удалены. Сигнатуры Python, поля и проверка JSON,
  версии артефактов, ID, порядок выходов и расчёты не изменились.
- Скалярные `update` и `transform` Python, а также `fit` и `fit_transform`
  конвейера больше не принимают `bid` и `ask`. Удалите эти аргументы даже со
  значением `None`: теперь они вызывают `TypeError`. Для снимков и дельт
  передавайте `OrderBookEvent` в `update_order_book` или `transform_order_book`.
  Числовые коды видов событий прежние; скалярный `KIND_ORDERBOOK` по-прежнему
  вызывает ошибку миграции.
- `TransformerDefinition` Rust теперь структура с публичными полями `input`,
  `output`, `operation`. Удобные конструкторы не изменились. Прямое создание
  варианта enum замените структурой с вариантом `TransformerOperation`;
  параметры разбирайте через `definition.operation`. Построители Python,
  JSON и численное поведение прежние. См.
  [пример миграции Rust](pipeline.md#scalar-definition-migration-rust).

<a id="added"></a>

### Добавлено

- Общие этапы графа с несколькими именованными выходами и независимо обученными
  ветвями sklearn, одной маской обучения и воспроизведением с пустым состоянием.
  Общие узлы исполняются один раз на принятое событие в каждом воспроизведении;
  Rust заимствует буферы выходов.
- Скалярные дельта, простая/логарифмическая доходность и временные лаги/изменения;
  скользящие std, min, max, range по отсчётам и времени; измерения траектории;
  экспериментальные сигнатуры пути со временем; серии и возраст состояний.
- Признаки добавленного/удалённого объёма bid/ask для напрямую применённых дельт.
- Завершены поведение и приёмочные проверки доходности по отсчётам и скользящей
  волатильности доходности в отдельных калькуляторах Rust, экстракторах,
  конвейерах и Python.
- Пример обучения нескольких выходов и общие фикстуры воспроизведения Python/Rust.
- Русская документация и команды сборки/проверки `just`.

<a id="fixed"></a>

### Исправлено

- Проверяемый разбор смещения UTC общий для JSON и построителей Python.
  Некорректные знаки компонентов и слишком большие числа теперь дают ошибки
  проверки, а не неверное смещение или панику. Пустое смещение запрещено;
  для нуля используйте `"UTC"` или `"+00:00"`. Корректные записи и канонический
  JSON не изменились.

- Временные SMA, OBV, число сделок, объём, VWAP и волатильность избегают
  переполнения на границах signed-int64. Выравнивание и истечение бакетов
  используют расширенную арифметику без сужения допустимых меток времени.

<a id="support"></a>

### Поддержка

- Rust 1.89+, CPython 3.12+ и пять существующих целей колёс сохранены.
- После загрузки воспроизведите прогрев и восстановите контекст. Свидетельства
  проверок приведены в [списке проверок выпуска](release-check-list.md).

<a id="020--2026-10-02"></a>

## 0.2.0 — 2026-10-02

<a id="breaking-changes-and-migration-1"></a>

### Несовместимые изменения и миграция

- SMA по отсчётам и EMA перенесены из экстрактора в преобразования конвейера.
  Замените `.sma(...)` / `.ema(...)` экстрактора Python и `FeatureKey::Sma` /
  `FeatureKey::Ema` Rust извлечением исходного поля и этапами SMA/EMA.
  Временная SMA и отдельные калькуляторы сохранены. Раскладки и ID исходных
  признаков меняются; задавайте явные выходные ID для сохранения имён столбцов.
  См. [руководство миграции средних](sample-average-migration.md).
- JSON экстрактора изменён с `1.1` на `2.0`, конвейера — с `2.6` на `3.0`.
  Старые форматы отклоняются. Пересоздайте и экспортируйте конфигурации, включая
  обученные конвейеры: одной замены номера JSON недостаточно.
- `OrderBook::apply_update(update, timestamp_millis)` Rust требует исходную метку
  Unix в миллисекундах. Сохраняйте метки источника при воспроизведении истории.
- `OrderBookConfig` Rust добавляет необязательное плотное хранилище `dense`,
  а `build()` возвращает `Result`. Предпочитайте `OrderBookConfig::new(...)`
  литералам структуры и обрабатывайте ошибки. `FeatureKey` больше не `Copy`,
  поскольку контекст владеет именами; заимствуйте или явно клонируйте ключи.
  Полные match должны учитывать новые варианты признаков, преобразований и
  ошибок; литералам `HandleEventResult` нужно поле `order_book_outcome`.

<a id="added-1"></a>

### Добавлено

- Извлечение исходных скаляров и SMA/EMA по наблюдениям, включая сглаживание
  стакана и композицию этапов. Средние продвигаются только на конечных наблюдениях;
  лаги по числу событий сохраняют прежнее поведение принятых событий.
- Предвычисленный контекст Rust/Python с атомарными частичными обновлениями,
  явной очисткой и расписанием при воспроизведении/обучении Python. Контекст
  не продвигает историю; доступностью и истечением управляет вызывающий код.
- Python `future_value` для целей по прошедшему времени: поиск назад/вперёд,
  допуск и необязательные детали совпадений. Нужен набор `pandas`; вызывайте
  отдельно для каждого инструмента и хронологической части данных.
- Необязательное плотное хранилище стакана на ограниченной десятичной сетке тиков
  с заранее выделенными уровнями и проверкой обновлений вне сетки/диапазона.
  Разреженный BTreeMap остаётся вариантом по умолчанию.
- В Rust: статус синхронизации стакана, исходные метки времени, результаты
  обработки стакана на событие, наблюдения источников исходных признаков и маски
  наблюдений конвейера. Настроенные стаканы обновляются даже без подписанных
  признаков. Метки источника сохраняются при воспроизведении буфера; свежесть
  определяется отдельно от готовности и синхронизации.
- Пример записи и воспроизведения частичной глубины Binance со сглаживанием и лагами.

<a id="support-1"></a>

### Поддержка

- Текст Apache-2.0 включён в crate Rust, wheel Python и исходный дистрибутив Python.
- Сохранены Rust 1.89+, CPython 3.12+, платформы wheel и наборы зависимостей 0.1.0.
- JSON хранит конфигурацию и обученные параметры, а не рабочее состояние.

<a id="010--2026-09-15"></a>

## 0.1.0 — 2026-09-15

Первый выпуск Fiml — потоковой библиотеки подготовки признаков для торговли и
машинного обучения с общим ядром Rust и привязками Python.

<a id="features"></a>

### Возможности

- Обработка цены, объёма, сделок, времени и стакана в повторно используемые векторы.
  В Rust можно заимствовать выходные срезы `f64`.
- Простая/логарифмическая доходность; SMA по отсчётам/времени; EMA; скользящая
  волатильность простых доходностей; временные число/объём сделок, VWAP; CVD, OBV,
  VPT; календарные признаки.
- Воспроизведение снимков/дельт стакана с проверкой последовательности, запросами
  котировок и глубины, спредом, средней и взвешенной средней ценой, микропрайсом,
  дисбалансом bid/ask.
- Настраиваемый прогрев, канонические ID и сериализация спецификаций экстрактора
  и конвейера с опубликованными JSON-схемами.
- Отбор, переименование, перестановка, масштабирование и лаги событий конвейера.
  Экспорт обученных масштабирований scikit-learn, заполнения пропусков, степенных/
  квантильных преобразований, отбора по дисперсии и PCA для Rust.
- Воспроизведение NumPy, необязательные pandas DataFrame и обучение scikit-learn.
  Python использует ядро Rust для согласованных исторических и живых расчётов
  при одинаковой конфигурации и порядке событий.
- Документированный API Rust, примеры Python, проверки совпадения и выделений
  памяти при установившихся обновлениях индикаторов/преобразований.

<a id="requirements-and-distribution"></a>

### Требования и распространение

- Rust 1.89+; CPython 3.12+ (заявлены 3.12–3.14).
- Python требует NumPy; наборы `pandas` и `sklearn` необязательны.
  `sklearn` требует scikit-learn `>=1.9,<1.10`.
- Артефакты: crate Rust, исходный дистрибутив Python, wheel для Linux
  x86-64/AArch64, macOS x86-64/AArch64, Windows x86-64.
  См. [выпуск GitHub](https://github.com/pbezglasny/fiml/releases/tag/v0.1.0).
- Лицензия Apache-2.0.

<a id="limitations"></a>

### Ограничения

- Полный прогрев выдаёт `NaN`; точные лаги доходности, отсутствующие уровни и пустые
  окна VWAP тоже могут оставлять выход недоступным. Обрабатывайте их до модели.
- Время — целые миллисекунды Unix epoch, неубывающие для символа по всем видам.
  Временные окна продвигаются событиями своего символа; глобальное время не
  продвигает окна других символов.
- JSON хранит конфигурацию и обученные параметры, а не историю и рабочий стакан.
  После загрузки восстановите историю воспроизведением событий.
- Создание, сериализация, выходы Python и стакан могут выделять память.
  Обновления без выделений ограничены встроенными индикаторами и преобразованиями
  с заранее выделенным хранилищем.
- Интернер имеет 512 слотов на процесс, включая глобальный; регистр ASCII не
  учитывается, слоты не освобождаются. Группа индикаторов поддерживает до 16
  совместимых выходов. Лаг конвейера — 1–10 000 принятых событий.
- Экспортируются только документированные оцениватели и параметры scikit-learn;
  произвольные оцениватели и интеграция `GridSearchCV` не поддерживаются.
  Обучение пока принимает только столбцовый API событий.
- RSI, MACD, полосы Боллинджера, ATR, ADX, стохастические осцилляторы и модель
  событий OHLC/баров отложены.

Подробности см. в [README](README.md#behavior-and-limits) и
[руководстве Python](crates/fiml-python/README.md).
