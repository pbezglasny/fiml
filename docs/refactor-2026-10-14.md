# Refactoring and implementation order — 2026-10-14

Status updated: 2026-10-20. The preparatory fixes and #164–#166 are implemented
and closed on GitHub. #167 is implemented in `af513a3` but remains open on GitHub.
#174 is implemented in this working tree; #175–#177 remain deferred.

## Decision

The UTC-offset fix, scalar transformer simplification, and #165–#167 feature work
are integrated. #174 replaces numeric indicator window storage; preserve
the shared feature compiler, static runtime dispatch, preallocated histories,
and common Python replay driver.

Keep each refactor separate from new numerical behavior. The purpose of the
preparatory work is to remove duplication that the next feature would otherwise
expand; the other cleanup does not block feature implementation.

  raw-feature caller.

### SMA benchmark comparison

Measured on an AMD Ryzen 9 9900X with rustc 1.98.1, the default release profile,
and Criterion's default 100 samples, 3-second warmup, and 5-second measurement.
No tests or builds ran concurrently with benchmark measurements.

```sh
cargo bench -p fiml --bench sma -- --save-baseline issue174-before
cargo bench -p fiml --bench sma -- --baseline issue174-before
```

Times below are Criterion's point estimates in microseconds per 10,000 updates.
The change column is Criterion's estimated time change, rather than a ratio of
the rounded point estimates. Positive changes mean slower execution.

| Group / storage / periods / windows | Before (µs) | After (µs) | Time change |
| --- | ---: | ---: | ---: |
| Update / stack / 20 / 1 | 21.666 | 22.052 | +1.63% |
| Update / stack / 20 / 3 | 34.538 | 35.316 | +2.27% |
| Update / stack / 200 / 1 | 23.514 | 23.350 | -0.97% |
| Update / stack / 200 / 3 | 34.846 | 35.456 | +1.86% |
| Update / heap / 20 / 1 | 22.384 | 22.114 | -1.49% |
| Update / heap / 20 / 3 | 40.272 | 40.266 | +0.40% (not significant) |
| Update / heap / 200 / 1 | 22.629 | 22.099 | -1.89% |
| Update / heap / 200 / 3 | 39.465 | 39.986 | +1.68% |
| Steady state / stack / 200 / 3 | 30.933 | 30.900 | -0.24% |
| Steady state / heap / 200 / 3 | 35.398 | 36.988 | +4.26% |

Because heap steady-state updates were slower, both steady-state cases were
repeated with:

```sh
cargo bench -p fiml --bench sma -- sma_steady_state --baseline issue174-before
```

The repeat measured stack at 30.794 µs (-0.54%, within Criterion's noise
threshold) and heap at 36.974 µs (+4.53%, 95% interval +4.20% to +4.94%).
The heap slowdown is repeatable on this machine and is not attributed to the
one-time initialization cost, since setup is excluded from this group.
Neither comparison crossed the plan's 5% threshold for further update-path
investigation; this smaller regression remains a measured tradeoff.

### Initialization cost and measurement limits

Construction now initializes every numeric window slot, including unused ones:
work proportional to `WINDOWS * size_of::<Window>()` (and to `VALUES` for timed
sums). Window addition still assigns the configured record. The compiler may
eliminate initialization that is overwritten before being observed. Storage
remains inline and initialization introduces no heap allocation; steady-state
loops visit only `window_count` records.

The existing SMA benchmarks configure every slot and use capacities of one or
three windows. Their update group includes construction followed by 10,000
updates; their steady-state group excludes construction from timing. They do
not isolate unused-slot initialization or measure large window capacities.
There are no existing direct benchmarks for the other migrated indicator
families, so no performance claim is made for those families.

representations must preserve fixture output order, NaN positions, observation
masks, clocks, warmup behavior, and Rust/Python parity.

- Run `cargo fmt --all` after Rust edits and verify formatting.

  public-interface changes; keep the full CI checks enabled.

  the new features or the UTC parser bug require them.

- Run relevant existing benchmarks for window-storage or book-query changes;
  record measurement gaps. #167 explicitly requires Criterion coverage.

  notes, and public documentation in the same change.
