# Fiml 0.3.0

This release adds shared transformation graphs with named model outputs,
additional rolling and stateful transformations, and timestamp-boundary fixes.

## Highlights

- Fit independent sklearn branches over shared stages and expose model and
  decision outputs from one event replay. Rust borrows output buffers without
  allocating; Python returns independent snapshots.
- Apply scalar delta/returns, elapsed-time lags and changes, rolling statistics,
  trajectory measurements, experimental path signatures, and streak/state-age
  transformations to preceding-stage features.
- Measure bid/ask volume added or removed by directly applied order-book deltas.
- Use completed sample-return and rolling return-volatility acceptance coverage
  across Rust and Python. Timed indicators handle signed-int64 timestamp extremes.
- Read the new Russian documentation and use `just` for development commands.

## Migration from 0.2.0

### Build a graph and name every output

Replace the old linear pipeline constructor/stage append API with
`root()` / `add(parent, stage)` / `output(name, node)` / `build()`.
Even a single output must be registered. There is no implicit final output or
pipeline-level `values()` accessor.

```python
import fiml
import numpy as np

raw = fiml.FeatureExtractorSpec().field("BTCUSDT", id="price")
spec = fiml.PipelineSpec(raw)
node = spec.add(spec.root(), fiml.ScalarStage().identity("price"))
spec.output("model", node)
pipeline = spec.build()
result = pipeline.transform(
    kind=np.array([fiml.KIND_PRICE], dtype=np.uint8),
    symbol=np.array([pipeline.symbol("BTCUSDT")], dtype=np.int64),
    timestamp=np.array([0], dtype=np.int64),
    price=np.array([100.0]),
)
assert list(result) == ["model"]
assert result["model"].shape == (1, 1)
assert pipeline.output_names() == ["model"]
assert pipeline.output("model").values()[0] == 100.0
```

`transform`, `fit_transform`, and `transform_order_book` return dictionaries of
matrices in output-registration order, including with only one output.
`compute_features` returns a dictionary of DataFrames. Select the desired name
before passing data to a model. Inspect each output through `output(name)`.
Register further names on existing or new nodes to share computation; each
stage resolves feature IDs against its direct parent. Fit estimator recipes
before inference/export; one `fit_mask` applies to all branches.

In Rust, construct `PipelineSpec::new(raw)`, add `FittedStage` nodes, register
outputs, and build. `pipeline.output("model")` returns an optional borrowed view
with `values()`, `feature_ids()`, and `observations()`. Retain its `id()` and use
`output_by_id(id)` across event updates; end value borrows before mutation.
See the [graph construction examples](https://github.com/pbezglasny/fiml/blob/v0.3.0/docs/multiple_output.md#rust-construction-and-borrowing)
and the [Python-to-Rust quickstart](https://github.com/pbezglasny/fiml/blob/v0.3.0/README.md#simple-example).

### Recreate pipeline artifacts

| Version | Meaning |
| --- | --- |
| `0.3.0` | Rust crate and Python package release |
| `4.0` | Pipeline JSON graph with ordered `nodes` and `outputs` |
| `2.0` | Nested feature-extractor JSON, unchanged in this release |

Pipeline JSON `3.0` is rejected. Recreate the graph and re-export the artifact
with 0.3.0; refit learned recipes before export. **Do not just change the version
string**: the graph structure and output registrations are required. JSON stores
configuration and fitted numeric parameters, not live values, clocks, indicator
or order-book history, or context values. Replay warm-up events and reapply
context after loading. Python `transform` advances runtime state; reset before
replaying an independent stream.

### Update removed arguments and Rust types

- Remove Python `bid` and `ask` arguments from `update`, `transform`, `fit`, and
  `fit_transform`, even if their value was `None`. Use `OrderBookEvent` with
  `update_order_book` / `transform_order_book`; scalar `KIND_ORDERBOOK` is rejected.
- Trade-only Rust `FeatureKey` variants no longer accept `source`. Scalar-source
  variants take `EventField` directly instead of `FeatureSource::Field(field)`.
- Construct `TransformerDefinition` with `input`, `output`, and `operation`
  fields, or keep using its convenience constructors. Match calculation
  parameters through `TransformerOperation` in `definition.operation`.

The [changelog](https://github.com/pbezglasny/fiml/blob/v0.3.0/CHANGELOG.md) lists affected variants and
correctness fixes. The [Python guide](https://github.com/pbezglasny/fiml/blob/v0.3.0/crates/fiml-python/README.md)
documents current signatures and order-book replay.

## Support and release status

Requires Rust **1.89+** or CPython **3.12+**. Wheels target Linux x86-64/AArch64,
macOS x86-64/AArch64, and Windows x86-64. NumPy is required; `pandas` and
`sklearn` extras remain optional. Licensed Apache-2.0.

Publication date is pending. The [release checklist](https://github.com/pbezglasny/fiml/blob/v0.3.0/docs/release-check-list.md)
tracks validation. Manual workflow dispatch builds artifacts without publishing;
pushing `v0.3.0` publishes through the existing release workflow.
