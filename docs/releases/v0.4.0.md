# Fiml 0.4.0

Release date: 2026-10-28.

Order-book deltas now support inclusive update-ID ranges, including aggregated
feed updates that overlap the next required ID. This release contains
[PR #207](https://github.com/pbezglasny/fiml/pull/207) and release documentation.

## Order-book updates

- Use `OrderBookDelta::new_range`, `OrderBookUpdate::new_delta_range`, or Python
  `OrderBookEvent.delta_range` for updates spanning multiple sequence IDs.
- `Contiguous` accepts a range covering the next required ID, both for direct
  updates and buffered replay after a snapshot. A range beginning after that ID
  still reports a gap; ranges ending at or before the last applied ID are stale.
- Level sizes remain absolute quantities; zero removes a level.
- Reversed bounds return `OrderBookUpdateError::InvalidUpdateRange` when applied
  in Rust, or `ValueError` when constructing the event in Python.

## Migration from 0.3.0

Rust field access and struct literals must replace `OrderBookDelta.update_id`
with `first_update_id` and `final_update_id`. Use `final_update_id` wherever the
old field represented the last applied sequence ID. Add `InvalidUpdateRange`
to exhaustive matches on `OrderBookUpdateError`.

```rust
use fiml::order_book::OrderBookDelta;

fn main() {
    let single = OrderBookDelta::new(101, vec![]);
    assert_eq!((single.first_update_id, single.final_update_id), (101, 101));

    let batch = OrderBookDelta::new_range(101, 105, vec![]);
    assert_eq!((batch.first_update_id, batch.final_update_id), (101, 105));
}
```

Existing `OrderBookDelta::new(id, changes)`,
`OrderBookUpdate::new_delta(id, changes)`, and Python `OrderBookEvent.delta(...)`
calls remain supported and set both bounds to the supplied ID.

```python
from fiml import OrderBookEvent

single = OrderBookEvent.delta(
    "BTCUSDT", timestamp=1000, update_id=101,
    changes=[("bid", "100", "2")],
)
batch = OrderBookEvent.delta_range(
    "BTCUSDT", timestamp=1001, first_update_id=102, final_update_id=105,
    changes=[("bid", "100", "3")],
)
```

Extractor JSON remains `2.0` and pipeline JSON remains `4.0`; 0.3.0 configuration
artifacts require no format migration or refitting for this release. Feature IDs
and output layouts are unchanged. JSON still does not contain live state;
replay warm-up events and reapply context after loading.

## Installation and support

```bash
cargo add fiml@0.4.0 --features serde
python -m pip install "fiml[pandas]>=0.4.0,<0.5"
```

Requires Rust **1.89+** or CPython **3.12+**. Wheels target Linux x86-64/AArch64,
macOS x86-64/AArch64, and Windows x86-64. NumPy is required; `pandas` and
`sklearn` extras remain optional. Licensed Apache-2.0.

See the [changelog](https://github.com/pbezglasny/fiml/blob/v0.4.0/CHANGELOG.md)
and [release checklist](https://github.com/pbezglasny/fiml/blob/v0.4.0/docs/release-check-list.md).
