# Fiml 0.2.0

This release adds composable moving averages, precomputed context, time-horizon
training targets, and more control over order-book storage and source freshness.

## Highlights

- Apply sample SMA/EMA to raw fields or other features in pipeline stages,
  including order-book smoothing. Only finite source observations advance them.
- Supply precomputed context alongside streaming features, with atomic updates
  and scheduled context changes during Python replay and fitting.
- Generate offline time-horizon labels with Python `future_value`, including
  lookup direction, tolerance, and match details.
- Choose preallocated dense order-book storage over a bounded decimal tick grid.
- Inspect Rust book synchronization, original source timestamps, per-event book
  outcomes, raw source observations, and pipeline observation masks. These let
  callers distinguish source age from feature readiness.
- Replay a recorded Binance partial-depth feed with the new Python example.

## Migration from 0.1.0

Sample SMA/EMA are now pipeline transformations. Replace extractor SMA/EMA with
raw field extraction and pipeline stages; standalone calculators and timed SMA
remain available. Raw IDs and layouts change, so use explicit output IDs where
model column names must stay stable.

Extractor JSON is now **2.0** and pipeline JSON is **3.0**. Older artifacts are
rejected. Rebuild and re-export configurations using the
[migration guide](https://github.com/pbezglasny/fiml/blob/v0.2.0/docs/sample-average-migration.md).

Rust `OrderBook::apply_update` now takes the original Unix-millisecond timestamp
as its second argument. `OrderBookConfig::build()` returns a `Result`, and config
struct literals need the new `dense` field; prefer `OrderBookConfig::new(...)`.
`FeatureKey` is no longer `Copy`; borrow or clone it explicitly. See the
[changelog](https://github.com/pbezglasny/fiml/blob/v0.2.0/CHANGELOG.md)
for additional public type changes.

## Support and limits

Requires Rust **1.89+** or CPython **3.12+**. Python wheel targets remain Linux
x86-64/AArch64, macOS x86-64/AArch64, and Windows x86-64. Licensed Apache-2.0.
The optional `pandas` extra is required for `future_value`.

JSON saves configuration and fitted parameters. Replay warm-up history and
reapply context after loading. Context expiry and source freshness are caller
policies. Dense book memory grows with the number of ticks in the configured
range; sparse storage remains the default. Generate training targets separately
for each instrument and chronological dataset partition.
